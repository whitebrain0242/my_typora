> [!note]- 整篇回答骨架
> 1. 为什么需要分层：异构设备互通、职责分离。
> 2. 应用层：HTTP、DNS 等，定义应用交互。
> 3. 传输层：TCP/UDP、端口、可靠性与分段。
> 4. 网络层：IP、子网掩码、寻址与路由、MTU。

## B｜面试问答闪卡

> [!tip] 答案阅读方式

### 01｜网络分层与整体模型


**Q01｜为什么不同设备通信需要网络协议？为什么要分层？**
?
- 不同设备的硬件、操作系统和实现方式不同，需要约定统一的通信规则。
- 分层把通信拆成职责清晰的模块：上层调用下层提供的服务，不必了解其全部实现细节。
- 这样便于标准化、互操作、独立演进与排查故障。
- **验收关键词**：统一协议；职责分离；屏蔽实现；互操作


**Q02｜请从上到下介绍 TCP/IP 四层模型及每层职责。**
?
- 应用层：为应用提供网络功能，如 HTTP、DNS、FTP、SMTP、Telnet。
- 传输层：为应用端点提供通信服务，典型协议 TCP、UDP。
- 网络层：使用 IP 地址寻址，并通过路由把 IP 包转发到目标网络。
- 网络接口层：在具体链路上传输帧，如以太网、Wi-Fi。
- **验收关键词**：顺序正确；每层职责；举例


**Q03｜TCP/IP 四层与 OSI 七层有什么关系？**
?
- TCP/IP 应用层大致对应 OSI 应用层、表示层、会话层。
- TCP/IP 传输层对应 OSI 传输层；网络层对应 OSI 网络层。
- TCP/IP 网络接口层大致对应 OSI 数据链路层和物理层。
- 这是帮助理解的近似对应，不代表两种模型逐层严格等价。
- **验收关键词**：七层对应；近似而非严格等价


### 02｜应用层


**Q01｜应用层负责什么？为什么不用自己实现 IP 路由？**
?
- 应用层定义应用间如何交换和解释数据，为用户提供具体网络功能。
- 它把待发送的数据交给下层协议栈，具体的传输、寻址、链路交付由下层承担。
- 例如 HTTP 规定请求和响应的语义，但不亲自选择路由器的下一跳。
- **验收关键词**：应用语义；下层服务；职责边界


**Q02｜请举例说明 HTTP、FTP、Telnet、DNS、SMTP 各做什么。**
?
- HTTP：Web 资源请求与响应；FTP：文件传输。
- Telnet：远程终端访问，通常不加密；DNS：域名相关信息查询与解析。
- SMTP：邮件发送与中继。
- 这些是应用层协议；不要把 DNS 误当作网络层协议。
- **验收关键词**：五个协议与用途


**Q03｜应用层与内核网络协议栈如何协作？**
?
- 通常应用程序运行在用户态，通过 Socket 等系统调用使用内核网络协议栈。
- 常见操作系统的 TCP/IP 传输、网络及链路处理主要由内核完成，网卡驱动和硬件协作发送。
- 这是常见实现，不是协议规定所有应用层处理必须在用户态，也不是所有网络栈都只能在内核。
- **验收关键词**：用户态；Socket；内核态；实现例外


### 03｜传输层与 TCP/UDP


**Q01｜传输层的核心职责是什么？与网络层怎么分工？**
?
- 传输层面向应用通信端点，利用端口进行复用与分用，提供 TCP 或 UDP 服务。
- 网络层面向跨网络的 IP 包寻址与转发；传输层不负责逐跳选路。
- 可以理解为网络层把包送到目标主机的网络接口，传输层再交给合适的通信端点。
- **验收关键词**：端到端；端口；IP 路由分工
<!--SR:!2026-10-20,0,230-->


**Q02｜面试官问 TCP 和 UDP 有什么区别，你怎么回答？**
?
- TCP 面向连接，提供可靠、有序的字节流服务，具有确认、重传、流量控制与拥塞控制等机制。
- UDP 无连接、保留数据报边界，协议本身不保证可靠到达或有序交付，头部开销较小。
- UDP 不等于一定更快；实际时延和吞吐还受网络、应用设计等因素影响。
- **验收关键词**：连接；可靠性；字节流/数据报；开销


**Q03｜TCP 为什么能提供可靠、有序传输？**
?
- 通过序列号标识字节顺序，接收方确认已收到的数据。
- 发生丢失时可根据超时或重复确认等信号重传；接收端按序重组并处理重复数据。
- 流量控制避免压垮接收方，拥塞控制调节向网络注入的数据量。
- TCP 可靠性是传输层语义，不保证应用已经持久化处理数据。
- **验收关键词**：序列号；ACK；重传；流控；拥塞控制


**Q04｜UDP 不可靠，那能不能在 UDP 上实现可靠传输？**
?
- 可以。UDP 本身只提供尽力而为的数据报传输。
- 应用层或基于 UDP 的协议可实现序列号、确认、重传、排序、拥塞控制等能力。
- 但可靠传输的设计与调优并不简单，也不是所有实时应用都需要完整可靠性。
- **验收关键词**：UDP 无保证；上层补机制；取舍


**Q05｜什么是 TCP MSS？为什么要进行分段？**
?
- MSS 是一个 TCP 报文段中 TCP 数据部分的最大长度，不包括 TCP 和 IP 头部。
- 应用写入的数据可能大于一次可承载的段大小，TCP 需要分段发送。
- 合理的 MSS 有助于避免报文超出路径承载能力，丢失时通常只需重传相应数据范围。
- **验收关键词**：MSS 不含头部；TCP 分段；重传范围


**Q06｜MSS 与 MTU 有什么区别？它们是什么关系？**
?
- MTU 是某条链路一次能够承载的最大网络层数据包大小；MSS 是 TCP 数据负载的最大长度。
- 典型以太网 MTU 为 1500 字节，IPv4 头 20 字节、TCP 头 20 字节且无选项时，常见 MSS 为 1460 字节。
- 实际 MSS 会受到 IP/TCP 选项、IPv6、路径 MTU 等因素影响，不能永远固定为 1460。
- **验收关键词**：MTU 对 IP 包；MSS 对 TCP 数据；典型 1500/1460


**Q07｜为什么需要端口号？IP 地址和端口号有什么区别？**
?
- IP 地址用于网络层定位网络接口并实现路由。
- TCP/UDP 端口用于区分同一主机上的通信端点，使传输层能够复用与分用数据。
- 端口不是进程 ID，也不是每个浏览器标签页都必须分配一个独立端口。
- **验收关键词**：IP 寻址；端口分用；不是进程 ID


**Q08｜服务端端口与客户端临时端口有什么区别？举例说明。**
?
- 服务端通常监听约定的端口，例如 HTTP 常用 TCP 80，SSH 常用 TCP 22。
- 客户端建立连接时，操作系统通常从临时端口范围选择源端口。
- 一个 TCP 连接通常由源 IP、源端口、目的 IP、目的端口共同标识（在 TCP 协议上下文中）。
- **验收关键词**：80/22；临时源端口；四元组


### 04｜网络层、IP 与子网


**Q01｜为什么已经有传输层，还需要网络层？**
?
- 互联网由多个网络、路由器和链路组成，跨网络送达需要统一寻址和逐跳转发。
- 传输层主要面向应用通信，网络层负责根据目标 IP 与路由信息转发 IP 包。
- 分工使传输协议不必亲自处理每一跳的链路与路径选择。
- **验收关键词**：跨网络；IP 寻址；逐跳转发


**Q02｜IP 协议主要做什么？是否保证可靠到达？**
?
- IP 为数据包提供源和目的 IP 地址，支持跨网络寻址与路由转发。
- IP 通常提供尽力而为、无连接的数据报服务，不承诺每个包一定到达、按序到达或只到达一次。
- TCP 等上层协议可以在此基础上提供更强的传输语义。
- **验收关键词**：寻址；路由；尽力而为


**Q03｜IP 包是怎样封装传输层数据的？**
?
- 网络层把 TCP 段或 UDP 数据报作为负载，在前面添加 IP 首部形成 IP 数据包。
- IP 首部包含源 IP、目的 IP 等转发所需字段。
- 接收方根据 IP 首部的协议字段把负载交给相应的上层协议。
- **验收关键词**：传输层负载；IP 头；协议字段


**Q04｜MTU 是什么？超过 MTU 就一定发生 IP 分片吗？**
?
- MTU 是链路层能承载的最大网络层包长度，以太网常见 MTU 为 1500 字节。
- IPv4 在允许分片且设备支持的情况下可能分片；若设置 DF 等条件，可能丢包并反馈需要减小包长。
- IPv6 中间路由器不执行分片，通常通过路径 MTU 发现由源端调整发送大小。
- 因此不能简单地说超过 MTU 一定分片。
- **验收关键词**：MTU；IPv4 条件分片；IPv6 不由路由器分片


**Q05｜IPv4 地址有多长？点分十进制表示是什么意思？**
?
- IPv4 地址为 32 位，通常写成四个十进制八位组，例如 192.168.100.1。
- 每个八位组有 8 位，取值范围是 0 到 255。
- IP 地址通常分配给网络接口，不能简单理解为一个设备永久对应唯一地址。
- **验收关键词**：32 位；四个八位组；接口


**Q06｜为什么要把 IP 地址分成网络部分和主机部分？**
?
- 网络前缀标识所属网络，主机部分区分该网络中的接口地址。
- 路由器可按网络前缀聚合和查找路由，不必为每个全球 IP 单独维护一条路径。
- 划分位置由子网掩码或 CIDR 前缀长度确定。
- **验收关键词**：网络前缀；主机部分；路由聚合


**Q07｜子网掩码是什么？CIDR 中 /24 表示什么？**
?
- 子网掩码中连续的 1 对应网络前缀位，0 对应主机位。
- /24 表示前 24 位属于网络前缀，对应掩码 255.255.255.0。
- 网络地址可由 IP 地址与掩码按位与得到。
- **验收关键词**：连续 1；/24；按位与


**Q08｜给定 10.100.122.2/24，如何计算网络地址与主机部分？**
?
- /24 对应掩码 255.255.255.0。
- IP 与掩码按位与，得到网络地址 10.100.122.0。
- IP 与掩码取反后的结果按位与，得到主机部分 0.0.0.2（低 8 位的数值为 2）。
- **验收关键词**：掩码；按位与；网络地址；主机部分


**Q09｜什么是 IP 寻址？什么是路由？两者如何配合？**
?
- 寻址是根据目的 IP 和网络前缀识别目的网络或下一跳相关信息。
- 路由是依据路由表与转发规则决定从哪个接口、交给哪个下一跳。
- 路由器通常使用最长前缀匹配选择适用路由，再逐跳转发。
- **验收关键词**：目的 IP；路由表；下一跳；最长前缀


**Q10｜目标 IP 不在本地子网时，主机会怎么处理？**
?
- 主机依据本地路由表判断目的地址不在直连网络。
- 通常把 IP 包交给默认网关（如果有适用的默认路由），而不是直接查询远端主机的 MAC。
- 在以太网场景下，先解析下一跳网关的 MAC，再封装链路帧发送。
- **验收关键词**：默认网关；下一跳 MAC；目的 IP 不变

### 05｜网络接口层、MAC 与 ARP


**Q01｜网络接口层负责什么？它与网络层有什么不同？**
?
- 网络接口层负责在当前IP头部加上MAC头部形成数据帧并传输帧，例如以太网或 Wi-Fi。
- 网络层关注跨网络的 IP 包和路由，网络接口层关注这一跳怎样把数据交给下一设备。
- 常见以太网帧包含源 MAC、目的 MAC、类型字段及校验等内容。
- **验收关键词**：逐跳；帧；IP 与 MAC 分工
<!--SR:!2026-10-20,0,230-->


**Q02｜以太网是什么？Wi-Fi 和以太网是同一个协议吗？**
?
- 以太网是 IEEE 802.3 系列有线局域网技术，Wi-Fi 通常基于 IEEE 802.11。
- 两者都可承载 IP 数据，但介质访问、帧格式和具体链路机制不同。
- 不能把 Wi-Fi 简单视为以太网本身；它们在 TCP/IP 模型中都属于网络接口层相关技术。
- **验收关键词**：802.3；802.11；同层不同技术


**Q03｜为什么有 IP 地址还需要 MAC 地址？**
?
- IP 地址服务于网络层跨网络寻址与路由。
- 以太网 MAC 地址用于当前链路上的帧寻址；跨路由器转发时，链路帧的源/目的 MAC 通常逐跳变化。
- 因此 IP 与 MAC 不重复，而是不同层次的地址。
- **验收关键词**：跨网络 IP；逐跳 MAC；不同层次


**Q04｜ARP 协议是干什么的？在跨子网场景解析谁的 MAC？**
?
- ARP 在 IPv4 的以太网等链路中，用于根据同一链路上的目标 IPv4 地址解析对应的 MAC 地址。
- 若目的 IP 位于本地链路，通常解析目的主机 MAC；若要经网关转发，则解析下一跳网关 MAC。
- ARP 与网络层、链路层的交界关系紧密，教材的分层归属可能不同；面试重点是说清作用和工作位置。
- **验收关键词**：IPv4→MAC；本地目的或网关；层次有争议


**Q05｜以太网 MAC 头部一般包含哪些信息？数据帧如何形成？**
?
- 发送端把 IP 包作为以太网帧的负载，添加含源 MAC、目的 MAC、EtherType 等信息的帧头。
- 以太网帧还包含帧校验序列 FCS（具体呈现取决于抓包层次）。
- 链路层按当前这一跳的 MAC 地址交付帧；下一跳路由器会重新封装适合出口链路的帧。
- **验收关键词**：源/目的 MAC；EtherType；FCS；逐跳重封装


### 06｜封装、解封装与综合面试


**Q01｜从浏览器发出 HTTP 请求到网卡发送数据，逐层封装的过程是什么？**
?
- 应用层形成 HTTP 请求消息。
- 若使用 TCP，传输层把数据组织成 TCP 段，添加 TCP 首部（端口等）。
- 网络层添加 IP 首部形成 IP 包（源/目的 IP 等）。
- 网络接口层为当前链路封装帧头等信息，由网卡发出。
- 接收端通常按相反方向逐层解封装；HTTP/3 使用 QUIC/UDP，不能把所有 HTTP 都说成必经 TCP。
- **验收关键词**：HTTP；TCP/UDP；IP；链路帧；反向解封装


**Q02｜TCP/IP 各层常用的数据单位叫什么？**
?
- 应用层：消息或报文（message），例如 HTTP message。
- TCP 传输层：段（segment）；UDP：数据报（datagram）。
- 网络层：IP 包/数据报（packet/datagram）；链路层：帧（frame）。
- 名称反映封装层次，不代表它们是完全不同种类的物理数据。
- **验收关键词**：message；segment；packet；frame


**Q03｜如果 A 向另一子网的 B 发送数据，IP 地址和 MAC 地址在路由过程中如何变化？**
?
- 在没有 NAT 等改写的普通 IP 转发场景下，IP 包的源/目的地址通常端到端保持不变。
- A 首先将帧发给本地下一跳网关，目的 MAC 是网关对应接口的 MAC，而不是远端 B 的 MAC。
- 每经过一台路由器，旧链路帧被处理并按下一条链路重新封装，源/目的 MAC 随链路改变。
- 路由器还会更新 IP 的 TTL（IPv4）或 Hop Limit（IPv6）等字段。
- **验收关键词**：IP 通常不变；MAC 逐跳变；网关；TTL

> [!important] 面试严谨性提醒
> - 端口不等于进程 ID，浏览器标签页也不一定一标签一进程或一端口。
> - HTTP/3 基于 QUIC/UDP，不能断言所有 HTTP 都基于 TCP。
