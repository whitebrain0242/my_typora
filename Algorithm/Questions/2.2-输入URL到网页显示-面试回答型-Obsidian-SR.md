## A｜整篇闭卷验收（不生成重复闪卡）

**题目：不看提示，从输入 URL 开始，完整口述直到页面显示的全过程。**

> [!note]- 参考骨架（口述完再展开）
> URL 解析 → DNS / 缓存 → Socket / 协议栈 → TCP 握手（典型场景）→ HTTPS 的 TLS → HTTP 请求 → TCP 分段 → IP 寻址/路由 → ARP / MAC 帧 → 网卡 → 二层交换机 → 路由器逐跳转发 → 服务器解封装处理 → HTTP 响应 → 浏览器解析与渲染。
>
> 例外：连接可能复用；缓存可能省略 DNS 或网络请求；HTTP/3 基于 QUIC/UDP；代理/NAT/负载均衡可能改变路径和地址。

**验收标准**：能按时间线讲清楚、说明各层负责什么、区分 IP 与 MAC、解释 DNS 缓存和交换机/路由器，并能说出重要例外。

## B｜面试问答卡片


### URL 与 HTTP


面试官问：在浏览器输入网址到页面显示，完整流程是什么？
?
- **参考回答**：先解析 URL，确认协议、主机、端口、路径；需要时进行 DNS 解析；选择连接和协议，典型 HTTP/1.1 over TCP 场景建立 TCP 连接，HTTPS 还需 TLS；发送 HTTP 请求；数据经 TCP/IP/链路封装，通过网卡、交换机、路由器传输；服务端解封装、处理请求并响应；浏览器解析资源、构建页面并渲染。现代浏览器可能使用缓存、复用连接、HTTP/2 或 HTTP/3，因此并非每次都完整执行所有步骤。
- **验收关键词**：URL→DNS→连接→请求→封装→转发→响应→渲染


URL 由哪些部分构成？省略路径会发生什么？
?
- **参考回答**：URL 通常包含 scheme（协议）、host（主机）、可选端口、path（路径）、query（查询参数）和 fragment（片段标识）。省略路径通常按 `/` 请求；服务器可能把根路径映射到 index.html 等默认资源，但不是浏览器必然请求 `/index.html`。fragment 不发送到 HTTP 服务器。
- **验收关键词**：scheme；host；port；path；query；fragment；根路径


浏览器解析 URL 后，HTTP 请求报文大致包含什么？
?
- **参考回答**：以 HTTP/1.1 为例：请求行（方法、请求目标、版本）、请求头、空行、可选消息体；常见 Host 头指定目标主机。HTTP/2 和 HTTP/3 的线上帧格式不同，不能把 HTTP/1.1 文本格式推广到所有版本。
- **验收关键词**：请求行；请求头；空行；请求体；版本差异


浏览器输入 https:// 与 http://，主要差别是什么？
?
- **参考回答**：HTTP 明文语义本身不提供加密；HTTPS 是 HTTP 经 TLS 保护的通信。传统 HTTPS 使用 TCP + TLS，HTTP/3 使用 QUIC（基于 UDP）并集成 TLS 1.3 安全机制。默认端口常见 HTTP 80、HTTPS 443。
- **验收关键词**：TLS；80/443；HTTP/3 例外


### DNS


为什么访问网站前通常需要 DNS？
?
- **参考回答**：域名便于人记忆，网络通信通常需要得到可连接的 IP 地址。浏览器或系统可从缓存、hosts 或 DNS 获取解析结果；有时通过代理等方式由另一端解析，因此不是所有请求都由本机现场发起 DNS 查询。
- **验收关键词**：域名到地址；缓存；例外


DNS 域名的层级如何组织？
?
- **参考回答**：域名自右向左层级逐渐降低：根域 `.`、顶级域如 `com`、二级域如 `example.com`、主机名如 `www.example.com`；末尾的点代表根域。权威服务器负责相应区域的权威数据。
- **验收关键词**：根域；TLD；权威；右高左低


请讲清楚一次典型 DNS 递归解析过程。
?
- **参考回答**：客户端把查询交给递归解析器；解析器先查缓存，未命中时可依次询问根服务器获得顶级域服务器指引，再向顶级域服务器获得权威服务器信息，最后从权威服务器取得记录并缓存、返回给客户端。实际过程可能因缓存、CNAME、转发等缩短或改变。
- **验收关键词**：递归解析器；根；TLD；权威；缓存


DNS 递归查询和迭代查询有什么区别？
?
- **参考回答**：递归查询要求被询问方负责给出最终答案或错误；迭代查询允许服务器返回下一步应询问的服务器信息（转介）。典型客户端向递归解析器发起递归查询，解析器向层级服务器迭代查询。
- **验收关键词**：递归给最终结果；迭代给转介


为什么不是每次打开网页都要查询根 DNS？
?
- **参考回答**：浏览器、操作系统、递归解析器等可能缓存结果；系统还可能检查 hosts 文件。DNS 记录有 TTL，缓存有效时可直接复用；缓存策略和具体顺序因系统与浏览器而异。
- **验收关键词**：多层缓存；hosts；TTL


DNS 只查询 A 记录吗？DNS 查询通常使用什么传输协议？
?
- **参考回答**：不只：A 对应 IPv4，AAAA 对应 IPv6，CNAME 提供别名，MX 用于邮件路由等。传统 DNS 常用 UDP/53，也支持 TCP/53；现代还有 DoT、DoH 等加密传输方式。
- **验收关键词**：A；AAAA；CNAME；UDP/TCP 53；DoH


### Socket、TCP 与协议栈


应用程序如何把 HTTP 数据交给操作系统发送？
?
- **参考回答**：典型应用通过 Socket API 创建连接并发送数据；协议栈负责传输层、网络层与链路层的相应处理，最终由网卡驱动及硬件发送。具体实现可能采用用户态网络栈或其他优化路径。
- **验收关键词**：Socket；协议栈；驱动


TCP 三次握手的报文顺序和状态是什么？
?
- **参考回答**：客户端发 SYN（进入 SYN-SENT）；服务端回复 SYN+ACK（进入 SYN-RECEIVED）；客户端回 ACK（进入 ESTABLISHED）；服务端收到最终 ACK 后进入 ESTABLISHED。
- **验收关键词**：SYN；SYN+ACK；ACK；状态


为什么 TCP 建立连接通常需要三次握手？
?
- **参考回答**：双方要协商初始序列号，并确认双向通信能力；第三次 ACK 让服务端确认自己的 SYN 已被对端收到，避免仅凭旧 SYN 就误认为连接已完整建立。不能简单说成三次握手保证后续数据永远可靠。
- **验收关键词**：序列号；双向确认；旧连接请求


TCP 连接的四元组是什么？端口有什么用？
?
- **参考回答**：通常用源 IP、源端口、目的 IP、目的端口标识 TCP 连接；端口帮助传输层把数据交给对应 Socket。客户端常用临时源端口，Web 服务端常监听 80 或 443。端口不等于进程 ID。
- **验收关键词**：源/目的 IP；源/目的端口；Socket


为什么 TCP 需要 MSS 分段？MSS 与 MTU 有什么关系？
?
- **参考回答**：TCP 把字节流组织成适合发送的段。MSS 是 TCP 负载的最大长度；MTU 是链路能承载的最大网络层包大小。典型以太网 MTU 1500、IPv4/TCP 首部各 20 字节且无选项时，MSS 常为 1460；实际受路径和选项影响。
- **验收关键词**：分段；MSS；MTU；1500/1460


TCP 报文段首部有哪些与网页请求密切相关的字段？
?
- **参考回答**：源/目的端口用于通信端点识别；序列号与确认号支持可靠有序传输；标志位如 SYN、ACK、FIN 表示控制信息；窗口用于流量控制；校验和用于差错检测。
- **验收关键词**：端口；序列/确认；标志；窗口；校验和


TCP 如何把接收到的数据交给 HTTP 服务？
?
- **参考回答**：操作系统先验证 IP 包并识别上层协议，再根据 TCP 连接信息匹配 Socket；TCP 处理序列、确认和重组，将有序字节流交给应用读取。HTTP 服务解析请求并生成响应。
- **验收关键词**：IP 协议号；四元组；重组；Socket


如何查看 Linux 上的 TCP 连接状态？
?
- **参考回答**：可用 `ss -tanp` 查看 TCP 连接与监听状态；一些环境也提供 `netstat -napt`。观察 LISTEN、SYN-SENT、SYN-RECV、ESTAB、TIME-WAIT 等状态，注意命令权限和系统差异。
- **验收关键词**：ss；netstat；TCP 状态


### IP、路由与 MAC


IP 层为 TCP 段增加了什么？
?
- **参考回答**：IP 层封装 IP 首部，包含源/目的 IP、协议标识（IPv4 中 TCP 协议号为 6）及生存时间 TTL 等信息。网络层依据路由表决定下一跳或出口接口。
- **验收关键词**：源/目的 IP；协议号 6；TTL；路由


多网卡主机如何选择出口网卡和源 IP？
?
- **参考回答**：系统依据目的地址查询路由表，通常按最长前缀匹配和策略路由等规则确定出口及下一跳；源地址选择再结合出口、地址作用域和系统规则决定。不能简单说路由表只负责选一个固定源 IP。
- **验收关键词**：路由表；最长前缀；源地址选择


默认路由和默认网关是什么？
?
- **参考回答**：默认路由如 IPv4 `0.0.0.0/0`，用于没有更具体匹配时的转发；下一跳常是默认网关的 IP。若存在更具体路由则优先使用。
- **验收关键词**：0.0.0.0/0；下一跳；最长前缀


为什么有了 IP 地址还需要 MAC 地址？
?
- **参考回答**：IP 用于跨网络寻址和转发；以太网 MAC 用于当前链路的帧交付。跨路由器时源/目的 MAC 往往逐跳变化，而在无 NAT 等地址改写的普通转发中，源/目的 IP 通常保持不变。
- **验收关键词**：跨网络 IP；逐跳 MAC；NAT 例外


以太网帧头通常有哪些关键字段？
?
- **参考回答**：目的 MAC、源 MAC、EtherType（如 IPv4 为 0x0800、ARP 为 0x0806），尾部还有 FCS 用于帧差错检测。不同链路技术帧格式并不完全相同。
- **验收关键词**：源/目的 MAC；EtherType；FCS


ARP 是如何得到下一跳 MAC 的？
?
- **参考回答**：主机先查 ARP/邻居缓存；未命中时在本地广播域发送 ARP 请求，目标 IPv4 地址对应设备应答其 MAC，随后缓存映射。跨子网发送时解析的是下一跳网关的 MAC，不是远端服务器 MAC。
- **验收关键词**：缓存；广播请求；应答；网关 MAC


ARP 缓存有什么作用？怎样在 Linux 查看？
?
- **参考回答**：缓存 IPv4 到链路地址的映射，减少重复 ARP 广播；可用 `ip neigh` 查看邻居表，部分环境可用 `arp -a`。缓存项可能老化或重新验证。
- **验收关键词**：邻居缓存；减少广播；ip neigh


### 网卡、交换机、路由器


网卡与网卡驱动分别负责什么？
?
- **参考回答**：协议栈把待发送的帧交给驱动/网卡；驱动管理设备和队列，网卡负责链路收发与部分硬件卸载。以太网物理层把数据编码为链路信号，接收时执行相反过程；不同介质不一定都是电信号。
- **验收关键词**：驱动；网卡；链路信号；硬件卸载


FCS 有什么作用？它能保证 TCP 可靠传输吗？
?
- **参考回答**：FCS 用于链路帧差错检测，校验失败的帧通常丢弃；它不负责端到端重传，也不能替代 TCP 的确认、序列号与重传机制。
- **验收关键词**：链路差错检测；非端到端可靠性


二层交换机依据什么转发数据帧？
?
- **参考回答**：交换机依据目的 MAC 查 MAC 地址表（MAC→端口映射），命中则转发到对应端口；通常从收到的帧的源 MAC 学习表项。它通常不根据 IP 目的地址进行二层转发。
- **验收关键词**：目的 MAC；MAC 表；源 MAC 学习


交换机不知道目标 MAC 对应哪个端口时怎么办？
?
- **参考回答**：典型二层交换机会对未知单播进行泛洪，向同一 VLAN 中除入端口外的其他合适端口发送；广播帧也通常在广播域内泛洪。安全策略、VLAN、生成树等可能限制实际转发。
- **验收关键词**：未知单播泛洪；VLAN；入端口


交换机与路由器最关键的区别是什么？
?
- **参考回答**：典型二层交换机在同一二层广播域内按 MAC 转发帧；路由器按目的 IP 和路由表在不同网络之间转发 IP 包，并在出口重新进行链路层封装。现实中也有三层交换机，不能仅凭设备名称判断全部能力。
- **验收关键词**：二层 MAC；三层 IP；重新封装


路由器收到以太网帧后怎样转发？
?
- **参考回答**：先校验并处理收到的链路帧，移除入站链路封装；检查 IP 头、更新 TTL/校验等；查路由表确定出口与下一跳；必要时通过 ARP 获取下一跳 MAC，重新封装出站帧并发送。
- **验收关键词**：解帧；查路由；TTL；ARP；重封装


为什么路由器每一跳都要更换 MAC 地址？
?
- **参考回答**：MAC 地址是当前链路的交付地址。下一跳设备不同，出口接口和链路可能也不同，因此需要新的链路帧头；IP 目的地址则继续指向最终目标（除 NAT、隧道等情况）。
- **验收关键词**：逐跳链路；新帧头；IP 目的地址


TTL 的作用是什么？
?
- **参考回答**：IPv4 TTL 在路由器转发时递减，减到无法继续转发时丢弃并可能发送 ICMP Time Exceeded；IPv6 对应 Hop Limit。它防止错误路由造成无限循环。
- **验收关键词**：逐跳递减；防环；ICMP


### 服务端响应与完整追问


服务器收到请求后怎样逐层解封装？
?
- **参考回答**：链路层检查帧并取出 IP 包；IP 层检查目的地址与上层协议；TCP 按连接信息和序列号处理并交付应用字节流；HTTP 服务解析请求，生成 HTTP 响应，再反向封装发出。
- **验收关键词**：帧→IP→TCP→HTTP；反向封装


HTTP 响应回来后，浏览器为什么不一定立刻显示完整页面？
?
- **参考回答**：浏览器需解析 HTML，可能继续请求 CSS、JS、图片等资源；构建 DOM/CSSOM、执行脚本、布局、绘制和合成。缓存、异步加载和渲染调度都会影响呈现时间。
- **验收关键词**：HTML；资源；DOM/CSSOM；布局绘制


页面显示完是否一定立刻 TCP 四次挥手？
?
- **参考回答**：不一定。HTTP/1.1 常使用持久连接，HTTP/2 可多路复用；连接可能复用或空闲后关闭。HTTP/3 使用 QUIC/UDP，不存在 TCP 四次挥手。
- **验收关键词**：Keep-Alive；连接复用；HTTP/3


DNS 查询成功但网页打不开，你会按什么层次排查？
?
- **参考回答**：先检查 URL、代理、浏览器报错和 DNS 解析结果；再检查到目标 IP 的路由、网络连通与端口；随后检查 TCP/TLS 握手、HTTP 状态码与服务端日志；最后检查页面资源和渲染错误。DNS 成功只证明解析环节成功。
- **验收关键词**：DNS；路由；端口；TLS；HTTP；渲染


面试官追问：整个过程中哪些地址可能变化，哪些通常不变？
?
- **参考回答**：应用请求目标域名/URL 表示逻辑目标；TCP 连接通常有固定四元组；在普通 IP 转发中源/目的 IP 通常不变，TTL 逐跳变化；以太网源/目的 MAC 随每一跳改变。NAT、代理、负载均衡会改变部分假设。
- **验收关键词**：URL；四元组；IP；TTL；MAC；例外


请用 90 秒回答「输入 URL 后发生了什么」并补上关键例外。
?
- **参考回答**：按 URL 解析→缓存/DNS→建立传输与安全连接→HTTP 请求→TCP/IP/链路封装→网卡/交换机/路由器→服务端处理响应→浏览器渲染的顺序组织。结尾说明连接可能复用，HTTPS 涉及 TLS，HTTP/3 走 QUIC/UDP，页面可能需要加载多个资源。
- **验收关键词**：顺序；各层职责；例外；可口述

> [!warning] 不要机械背错
> - 无路径 URL 请求的通常是 `/`，是否返回 index.html 由服务器配置决定。
> - 现代 HTTPS 和 HTTP/3 不能都简化为“先 TCP 三次握手，再 HTTP”。
> - 交换机的 MAC 表通常通过**源 MAC** 学习，按**目的 MAC** 查表转发。
> - 跨网段 ARP 通常解析下一跳网关，而不是远端服务器的 MAC。
> - IP 在普通转发时通常保持源/目的地址，但 NAT 等会改写。
> - 浏览器显示页面后，TCP 连接不一定立刻关闭。
