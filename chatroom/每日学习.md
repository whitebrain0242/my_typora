你这个学习清单整体是对的，但顺序需要调整。

| 多线程                    | 必须     | 服务端并发、业务线程池     |

| 技术                       | 建议程度 | 原因                                           |

| ----------------------- | ---------------------------------------- |
| MQ                      | 可以了解思想，不建议两人项目里强行接入   |

| 复杂 JavaWeb 前后端分离 | 不建议作为主线，否则会偏离聊天室验收要求 |

你的项目要求是 **Java + Netty/NIO + MySQL/RDBMS**。
所以最终项目里，**MySQL 必须是主存储**。Redis 可以加，但只作为辅助。

# 五、Redis 应该怎么加进你的项目

你提到“之前的 md 文件没有 Redis，我觉得两个月可以学一下”，这个想法是对的。

但 Redis 不应该替代 MySQL，而应该作为增强功能。

## 推荐 Redis 使用点 1：验证码

原来设计中验证码在 MySQL：

```text
verify_codes 表
```

可以改成：

```text
Redis 存验证码
MySQL 可选存验证码使用记录
```

Key 设计：

```text
verify:register:email:alice@example.com -> 839201
verify:login:email:alice@example.com -> 293810
verify:reset:email:alice@example.com -> 771902
```

过期时间：

```text
5 分钟
```

对应方法：

```java
public void sendEmailCode(String email, VerifyCodeScene scene);
public boolean verifyEmailCode(String email, String code, VerifyCodeScene scene);
```

------

## 推荐 Redis 使用点 2：登录失败次数限制

防止暴力破解。

Key：

```text
login:fail:alice
```

逻辑：

```text
登录失败一次，Redis 中次数 +1
设置 10 分钟过期
失败超过 5 次，暂时禁止登录
登录成功后删除该 key
```

对应方法：

```java
public void recordLoginFail(String username);
public boolean isLoginBlocked(String username);
public void clearLoginFail(String username);
```

------

## 推荐 Redis 使用点 3：临时通知摘要

比如用户上线后显示：

```text
你有 3 条未读私聊
你有 2 条群消息
你有 1 个好友申请
```

可以 MySQL 查询，也可以 Redis 缓存摘要。

Key：

```text
notify:unread:user:1001
```

不过这个不是必须。

------

## 不推荐 Redis 做的事情

不要这样做：

```text
用 Redis Pub/Sub 做聊天
用 Redis 存全部聊天记录
客户端直接连接 Redis
多个 Redis 实例
```

你们项目应该保持：

```text
客户端 -> Netty 服务端 -> MySQL / Redis
```

而不是：

```text
客户端 -> Redis
```
