## 第十五章 文件属性

### 15.1 stat()

英文;status 名词状态

**是什么？**

>  是用来获取文件信息的，准确说是获取文件的属性的

用法如下：

```c
struct stat sb;

if (stat("a.txt", &sb) == -1) {
    perror("stat");
}
```

获取a.txt的属性存入sb结构体内

**返回值** 成功》返回0

​           失败》返回-1

`struct stat`是一个结构体，装着各种属性

```c
struct stat {
    dev_t     st_dev;      // 文件所在设备
    ino_t     st_ino;      // inode 号
    mode_t    st_mode;     // 文件类型和权限
    nlink_t   st_nlink;    // 硬链接数
    uid_t     st_uid;      // 文件属主用户 ID
    gid_t     st_gid;      // 文件所属组 ID
    off_t     st_size;     // 文件大小
    time_t    st_atime;    // 最后访问时间
    time_t    st_mtime;    // 最后修改时间
    time_t    st_ctime;    // 最后状态改变时间
};
```

stat()：会跟随链接进入这个文件，获取链接里面的文件信息

lstat()：不会跟随进入文件，而是获取这个链接本身的属性

fstat()：上面都是根据路径查文件，这个是根据文件描述符fd

#### st_mode

文件类型和权限：包含两个方面——》**文件类型和文件权限**

文件类型：普通文件，目录，符号链接等-----》**一切皆文件**

```c
普通文件      比如 a.txt、main.c
目录          比如 /home、/etc
符号链接      类似快捷方式
字符设备      比如终端、键盘
块设备        比如磁盘
FIFO          命名管道
socket        网络通信相关
```

文件权限：读写执行

##### 判断文件类型

```c
S_ISREG(sb.st_mode)   // 是否普通文件
S_ISDIR(sb.st_mode)   // 是否目录
S_ISLNK(sb.st_mode)   // 是否符号链接
S_ISCHR(sb.st_mode)   // 是否字符设备
S_ISBLK(sb.st_mode)   // 是否块设备
S_ISFIFO(sb.st_mode)  // 是否 FIFO/管道
S_ISSOCK(sb.st_mode)  // 是否 socket
     
     if (S_ISREG(sb.st_mode)) {
    printf("普通文件\n");
} else if (S_ISDIR(sb.st_mode)) {
    printf("目录\n");
}

```

### 15.2  文件时间戳

linux里面有三个很重要的时间就是

atime——最后访问时间——access time——最后一次被读取的时间

mtime——最后修改时间——modification time——最后一次被修改的时间

ctime——最后状态改变时间——change itime——最后状态改变的时间

```c
权限变化
属主变化
所属组变化
硬链接数变化
文件大小变化
文件内容变化
```

**注意**atiem不一定每一次读操作 都会改变，为了性能，可能不更新

```c
relatime：相对更新 atime，减少磁盘写入
noatime：不更新 atime
```

#### **怎么修改它？**

##### utine()

```c
#include <utime.h>

int utime(const char *filename, const struct utimbuf *times);
```

它可以修改文件的atime mtime 但是不能直接修改ctime

因为一般**ctime是由内核自动维护的**，就是说你改变atime和mtime的时候，内核自动跟新ctime

##### utimes()

它的精度比utime更高，精度到了微秒

##### utimensat()  futimens()

更加现代的接口

```c
utimensat()  根据路径修改时间
futimens()   根据 fd 修改时间
```



### 15.3 文件属主

#### 有什么用？

让系统知道这个文件属于谁，属于哪一个组，当前访问者是谁，访问者是哪一个组的——判断是否可以访问

#### 新建属主

一般创建文件的时候属主是创建者

而对于属组：1.当前用户的主组2.设置了setgit 继承目录下的所属组

#### 改变文件属组 chown()、fchown()、lchown()

```c
#include <unistd.h>

int chown(const char *pathname, uid_t owner, gid_t group);//根据路径修改文件属主和组。
int fchown(int fd, uid_t owner, gid_t group);//根据已经打开的文件描述符修改属主和组。
int lchown(const char *pathname, uid_t owner, gid_t group);
//如果目标是符号链接，lchown() 修改符号链接本身，而不是它指向的文件

```

#### 谁能改变文件属主？

ROOT可以，普通用户不可哟

### 15.4 文件权限

三类用户：

文件所有者 user
       文件所属组 group
       其他用户 other

三种权限：r  读
                        w  写——但不能删除
                        x  执行

```c
-rw-r--r--
-    rw-    r--    r--
类型  属主   所属组  其他人
r = 4
w = 2
x = 1
```

#### 目录权限

| 权限 | 普通文件     | 目录                     |
| ---- | ------------ | ------------------------ |
| r    | 读文件内容   | 列出目录文件名           |
| w    | 修改文件内容 | 创建、删除、重命名目录项 |
| x    | 执行文件     | 进入目录、搜索路径       |

#### 权限检查算法

判断你是否可以访问一个文件一般有以下步骤

```c
1. 如果你是 root，通常权限最大
2. 如果你是文件属主，看 user 权限
3. 否则如果你属于文件所属组，看 group 权限
4. 否则看 other 权限
```

>  Linux 只会选择一类权限来判断，不是三类权限叠加。

如果你是文件属主，就看 user 权限；
 即使 group 权限更大，也不会再用 group 权限补充。



你对路径访问也需要权限，要检查每一级的执行权限也就是x权限

#### access()

检查访问权限，看你是否有权限能够访问某个文件

```c
#include <unistd.h>

int access(const char *pathname, int mode);
mode：
F_OK   文件是否存在
R_OK   是否可读
W_OK   是否可写
X_OK   是否可执行
例如：
     if (access("a.txt", R_OK) == 0) {
    printf("可以读取\n");
} else {
    printf("不能读取\n");
}

```

要小心

```c
if (access("a.txt", W_OK) == 0) {
    int fd = open("a.txt", O_WRONLY);
}
```

你虽然先看了权限，再打开，但是不确定在你看完权限之后有没有变动，文件状态可能被改掉——**TOCTOU 问题**

#### Set-User-ID、Set-Group-ID 和 Sticky 位

普通权限rwx

特殊权限

```c
Set-User-ID    SUID
Set-Group-ID   SGID
Sticky bit     粘滞位
```

1.SUID

如果一个可执行文件设置了 SUID 位，那么普通用户运行它时，程序会临时拥有文件属主的权限。

比较危险

2.SUID

对可执行文件——如果可执行文件设置了 SGID，运行时程序临时拥有文件所属组的权限

对目录——如果目录设置了 SGID，那么在这个目录中创建的新文件，会继承该目录的所属组。

3.Sticky bit：粘滞位

`/tmp` 是公共临时目录，很多用户都可以在里面创建文件。

但如果没有 sticky bit，用户 A 可能删除用户 B 的文件。

```c
目录里每个人都可以创建文件
但只能删除自己的文件
root 和目录所有者除外

```

#### umask

`umask` 决定新建文件时哪些权限要被去掉。

```c
最终权限 = 申请权限 & ~umask
```

比如说一个文件里面你设置了所有文件都可以改变的权限，但是umask规定了自己只能改变自己的文件，这个时候你申请的权限会受到umask的影响

umask函数

```c
umask(0022);
umask 是进程属性
子进程会继承父进程的 umask

```

#### chmod()和fchmod()

更改文件权限

chmod是根据文件路径改变的

fchmod是根据文件描述符改变的

有时候权限是四位数

```c
0755
最前面的 0 表示这是八进制。
     如果涉及特殊权限位，可能是：4755 2755 1777
     其中第一位表示特殊权限：
     4 = SUID
     2 = SGID
     1 = Sticky


```

### 15.5 inode标志

```c
普通权限控制的是：
谁能读、写、执行
     
inode 标志控制的是更底层的文件行为，比如：
文件不可修改
文件只能追加
不更新访问时间
删除时安全擦除
```

比如说

```c
lsattr file
chattr +i file
chattr +a file
```

####  immutable：不可变标志

`chattr +i a.txt`

设置后，文件变成不可变。即使 root，也不能随便修改、删除、重命名这个文件，除非先去掉这个标志。

#### append-only：只能追加

`chattr +a log.txt`

设置后，文件只能追加写，不能覆盖、不能截断、不能删除。

#### noatime：不更新访问时间

有些文件可以设置不更新 atime，减少磁盘写入。



chmod控制的是用户权限，谁可以读写执行

inode控制的是文件系统级别的行为能不能被修改  能不能被删除  是否只能追加
