## 第十八章 目录与链接

### 18.1 目录和硬链接

目录也是一种特殊文件，里面保存的是**inode号**

所以说目录的本质就是保存 **名字和inode对应关系** 的表

```c
a.txt  -> inode 1001
b.txt  -> inode 1002
test   -> inode 1003
```

**那么inode又是什么？**

inode可以储存

```c
文件类型
文件权限
文件大小
文件属主
文件时间戳
文件数据块位置
硬链接数量
```

但是inode通常不保存文件名，文件名保存在目录里

>  文件名在目录里；
>  文件属性在 inode 里；
>  文件内容在数据块里。

#### 硬链接是什么？

就是给同一个inode在起一个名字

```c
比如你有文件：
echo hello > a.txt
然后创建硬链接：为a.txt创建硬链接b.txt
ln a.txt b.txt
这时 a.txt 和 b.txt 都指向同一个 inode。
```

##### 如何看硬链接是否指向一个inode？

```c
ls-li
```

如果第一个显示的inode号相同就是同一个文件

```c
1001 -rw-r--r-- 2 jordan jordan 12 May 10 a.txt
1001 -rw-r--r-- 2 jordan jordan 12 May 10 b.txt
```

中间的2是硬链接数

##### 删除了一个硬链接之后，文件会被删除吗？

如果删完这一个还有另外一个硬链接存在，那么不会被删除，只是删除了目录的名字

等到最后一个硬链接也被删除的时候，并且没有进程打开这个文件的时候，文件数据才会被释放

```c
1. 硬链接数变成 0
2. 没有进程还打开着它
```



##### 硬链接不能跨文件系统

可能磁盘A有inode1001

磁盘bye有inode1001,但是两个指的不是一个东西，所以不能跨系统

##### 普通用户不能创建硬链接

>原因是：

>  如果目录可以随便硬链接，文件系统树可能形成环，遍历和删除会变得非常复杂。

```c
A 目录里链接到 B
B 目录里又链接回 A
```

### 18.2 符号链接——软链接

创建方式

```c
ln -s a.txt link.txt
link.txt 是一个特殊文件
它里面保存的是路径名 a.txt
```

#### 软连接和硬链接的区别

硬链接是多个名字指向用一个inode

软链接时一个特殊文件，保存的时另一个文件的路径

##### 软连接可以跨系统

它保存的时路径名而不是inode，所以可以跨系统，

##### 软连接可以指向目录

使用cd跳入软连接，实际上是跳到了软链接存的那个文件里

##### 软连接可能失效

```c
如果你创建：
ln -s a.txt link.txt
然后删除：
rm a.txt
这时 link.txt 还在，但它指向的目标没了。
```

**这就是悬空链接**，快捷方式还在，但是原文件已经没有了

| 对比             | 硬链接                                 | 软链接                   |
| ---------------- | -------------------------------------- | ------------------------ |
| 本质             | 多个文件名指向同一个 inode             | 一个文件保存另一个路径   |
| 是否有独立 inode | 没有新的文件内容，但目录项指向同 inode | 软链接本身有自己的 inode |
| 能否跨文件系统   | 不能                                   | 可以                     |
| 能否链接目录     | 一般不允许                             | 可以                     |
| 目标删除后       | 其他硬链接仍可用                       | 软链接失效               |
| 类似于           | 一个文件多个名字                       | 快捷方式                 |

### 18.3 link() 和 unlink()

创建和移除硬链接

**link()**创建硬链接

```c
#include <unistd.h>

int link(const char *oldpath, const char *newpath);
给 oldpath 对应的文件，再创建一个名字 newpath
//也就是让两个指向同一个inode
```

**unlink()** 用来删除一个文件名，也就是删除目录项。

```c
#include <unistd.h>

int unlink(const char *pathname);
unlink("a.txt");==rm a.txt
```

unlink() 删除的是文件名，不一定马上删除文件内容。

**解除文件名和 inode 之间的链接**

利用文件真正被删除的特性，可以

```c
int fd = open("a.txt", O_RDONLY);
unlink("a.txt");
这时目录里已经看不到 a.txt 了。
但是因为进程还打开着它，所以文件内容暂时还存在。
close(fd);之后，如果没有其他硬链接，文件才真正释放
```

用法：

```c
int fd = open("tmpfile", O_RDWR | O_CREAT | O_EXCL, 0600);
unlink("tmpfile");
文件已经没有名字
其他程序找不到它
但当前进程还能通过 fd 使用它
进程关闭 fd 后，文件自动消失
```

```c
#include <stdio.h>

int rename(const char *oldpath, const char *newpath);
rename("old.txt", "new.txt");==mv old.txt new.txt

     
2. rename() 它也可以移动路径：

类似：
mv a.txt dir/a.txt
```

#### 一个重要特点：原子性

什么意思？

```c
要么旧名字还在
要么新名字已经生效
不会出现中间状态
```

##### 如果说new'path已经存在了

就是想改名字但是这个名字已经被其他文件用了，此时它会被替换掉

```c

非空目录通常不能被随便替换

```

### 18.5 symlink() 和 readlink()

symlink()创建软链接。

```c
#include <unistd.h>

int symlink(const char *target, const char *linkpath);

例如：
symlink("a.txt", "link.txt");
类似：
ln -s a.txt link.txt
注意参数含义：
target   链接里面保存的目标路径
linkpath 新创建的软链接文件名
```

 readlink()读取软链接里面保存的路径。

```c
#include <unistd.h>

ssize_t readlink(const char *pathname, char *buf, size_t bufsiz);

eg：
char buf[1024];

ssize_t n = readlink("link.txt", buf, sizeof(buf) - 1);
if (n == -1) {
    perror("readlink");
} else {
    buf[n] = '\0';
    printf("link points to: %s\n", buf);
}

```

readlink() 读出来的字符串不会自动加 `\0` 结尾。

所以要自己加：

```
buf[n] = '\0';
```

这是一个容易踩坑的点。

####  stat() 和 lstat() 对软链接的区别

```c
ln -s a.txt link.txt
stat("link.txt", &sb);
实际是a.txt 的属性
但是
     lstat("link.txt", &sb);
实际是link.txt 这个软链接本身的属性
所以说
     stat() 跟随软链接
lstat() 不跟随软链接

```

### 18.8 opendir() 和 readdir()

读目录

#### 为何不直接使用read目录？

因为不用文件系统里面的**目录内部格式**可能不一样

#### opendir()

打开目录流

```c
#include <dirent.h>

DIR *opendir(const char *name);
DIR *dirp = opendir(".");
. 表示当前目录。
```

#### readdir()

readdir() 会读到 . 和 ..

读取目录项：

```c
struct dirent *readdir(DIR *dirp);
```

每次读取一个目录项

```c
struct dirent {
    ino_t d_ino;          // inode 号
    char  d_name[];       // 文件名
};
entry->d_name

```

#### closedir()

用完目录后关闭：

```
closedir(dirp);
```

#### ls小练习

列出当前目录文件名

```c
#include <stdio.h>
#include <dirent.h>

int main(void) {
    DIR *dirp = opendir(".");
    if (dirp == NULL) {
        perror("opendir");
        return 1;
    }

    struct dirent *entry;

    while ((entry = readdir(dirp)) != NULL) {
        printf("%s\n", entry->d_name);
    }

    closedir(dirp);
    return 0;
}
```

### 18.9 nftw()

文件树遍历 遍历整个目录树

nftw() 的思路

你给 `nftw()` 一个起点目录和一个回调函数。

它会自动遍历目录树。

每遇到一个文件或目录，就调用你的回调函数

```c
nftw("dir", callback, ...)
    遇到 dir/a.txt  -> 调用 callback
    遇到 dir/sub    -> 调用 callback
    遇到 dir/sub/b  -> 调用 callback
```

### 18.10进程的当前工作目录

每个进程都有一个当前工作目录，简称 CWD。

pwd
看到的就是当前工作目录。

#### 绝对路径和相对路径

绝对路径从 `/` 开始：

```
/home/jordan/a.txt
/etc/passwd
/var/log/syslog
```

相对路径不从 `/` 开始：

```
a.txt
../test.txt
./main.c
```

相对路径要依赖当前工作目录。

获取当前工作目录：

`char *getcwd(char *buf, size_t size);`

```c
char buf[1024];

if (getcwd(buf, sizeof(buf)) == NULL) {
    perror("getcwd");

    printf("cwd = %s\n", buf);
}

```

#### chdir()

改变当前工作目录：

`int chdir(const char *path);`

#### fchdir()

根据目录文件描述符改变当前工作目录：

```
int fchdir(int fd);
```

```c
int fd = open("/home/jordan", O_RDONLY | O_DIRECTORY);
fchdir(fd);
这会把当前工作目录切换到 /home/jordan。
```

### 18.11 针对目录文件描述符的相关操作

这一节通常会涉及 `openat()`、`fstatat()`、`unlinkat()`、`mkdirat()`、`renameat()` 这一类函数。

它们的特点是：

>  不再只根据当前工作目录解析相对路径，而是根据某个目录 fd 解析路径。

------

## 1. 为什么需要 openat() 这一类函数？

普通 `open()`：

```
open("a.txt", O_RDONLY);
```

这里的 `a.txt` 是相对于当前工作目录解释的。

但如果多线程程序中，另一个线程突然调用了：

```
chdir("/tmp");
```

那么相对路径的含义就变了。

这可能很危险。

`openat()` 可以指定：

```
相对哪个目录打开文件
```

这样更安全。

------

## 2. openat() 示例

```
int dirfd = open("/home/jordan", O_RDONLY | O_DIRECTORY);

int fd = openat(dirfd, "a.txt", O_RDONLY);
```

这里 `a.txt` 会被理解为：

```
/home/jordan/a.txt
```

而不是当前工作目录下的 `a.txt`。

------

## 3. 通俗理解

普通 `open()` 像是：

```
从你当前所在位置找 a.txt
```

`openat()` 像是：

```
从我指定的这个目录开始找 a.txt
```

这样路径解析更可控。

------

## 4. 常见 at 系列函数

```
openat()     相对于目录 fd 打开文件
fstatat()    相对于目录 fd 获取文件属性
unlinkat()   相对于目录 fd 删除文件或目录
mkdirat()    相对于目录 fd 创建目录
renameat()   相对于目录 fd 重命名
symlinkat()  创建符号链接
readlinkat() 读取符号链接
```

这些函数在安全程序、服务器程序、多线程程序中很有用。

十四、18.12 改变进程的根目录：chroot()

## 1. chroot() 是什么？

`chroot()` 可以改变进程看到的根目录 `/`。

函数原型：

```
#include <unistd.h>

int chroot(const char *path);
```

例如：

```
chroot("/var/jail");
```

之后这个进程看到的 `/` 就不再是真正的系统根目录，而是：

```
/var/jail
```

也就是说，在这个进程看来：

```
/var/jail
```

变成了：

```
/
```

------

## 2. chroot 的用途

常用于限制程序活动范围。

比如你有一个服务程序，不希望它访问整个系统，只希望它在某个目录里活动。

可以把它关进：

```
/var/jail
```

这就是所谓：

```
chroot jail
```

通俗理解：

```
chroot 像是把程序关进一个房间。
程序以为这个房间就是整个世界。
```

------

## 3. chroot 不是完整安全容器

需要注意：

>  chroot 不是 Docker，也不是完整沙箱。

如果配置不好，尤其是进程有 root 权限时，可能逃逸。

所以它只是一个基础隔离手段，不是现代容器安全的全部。

十五、18.13 解析路径名：realpath()

1. realpath() 是什么？

`realpath()` 用来把路径解析成规范的绝对路径。

比如：

```
./dir/../a.txt
```

可能会被解析成：

```
/home/jordan/a.txt
```

它会处理：

```
.
..
符号链接
相对路径
多余的 /
```

2. 示例

```
#include <stdlib.h>
#include <stdio.h>

int main(void) {
    char *path = realpath("./a.txt", NULL);

    if (path == NULL) {
        perror("realpath");
        return 1;
    }

    printf("%s\n", path);
    free(path);

    return 0;
}
```

如果当前目录是：

```
/home/jordan
```

输出可能是：

```
/home/jordan/a.txt
```

## 3. 通俗理解

realpath()` 像导航软件帮你整理路线。

你给它：

```
从这里走，先进 dir，再返回上一级，再找 a.txt
```

它告诉你最终的真实位置：

```
/home/jordan/a.txt
```

十六、18.14 解析路径名字符串：dirname() 和 basename()

这两个函数处理的是路径字符串。

它们不一定真的访问文件系统，主要是拆字符串。

## 1. basename()

`basename()` 取路径最后一部分。

例如：

```
/home/jordan/a.txt
```

basename 是：

```
a.txt
```

## 2. dirname()

`dirname()` 取路径的目录部分。

例如：

```
/home/jordan/a.txt
```

dirname 是：

```
/home/jordan
```

## 3. 示例

```
#include <libgen.h>
#include <stdio.h>

int main(void) {
    char path1[] = "/home/jordan/a.txt";
    char path2[] = "/home/jordan/a.txt";

    printf("dirname: %s\n", dirname(path1));
    printf("basename: %s\n", basename(path2));

    return 0;
}
```

输出：

```
dirname: /home/jordan
basename: a.txt
```

注意：

>  dirname() 和 basename() 可能会修改传入的字符串，所以最好传入可修改的字符数组，不要直接传字符串常量。

不要这样：

```
basename("/home/jordan/a.txt");
```

更安全的方式是：

```
char path[] = "/home/jordan/a.txt";
basename(path);
```

# 十七、这一章最重要的底层原理

现在把这一章核心原理串起来。

假设你有：

```
/home/jordan/a.txt
```

文件系统解析路径时，大概是：

```
从根目录 / 开始
找到 home
进入 home 目录
找到 jordan
进入 jordan 目录
找到 a.txt
通过 a.txt 找到 inode
通过 inode 找到文件属性和数据块
```

路径解析过程：

```
/ -> home -> jordan -> a.txt -> inode -> 文件内容
```

所以，文件名不是文件本体。

文件名只是目录里的一个入口。

# 十八、删除文件、重命名文件的本质

## 1. 删除文件的本质

执行：

```
rm a.txt
```

本质是：

```
从目录中删除 a.txt 这个名字
```

也就是：

```
a.txt -> inode 1001
```

这个映射关系被删除。

如果没有其他名字指向 inode，且没有进程打开它，文件数据才释放。

------

## 2. 重命名文件的本质

执行：

```
mv old.txt new.txt
```

本质是修改目录项：

```
old.txt -> inode 1001
```

变成：

```
new.txt -> inode 1001
```

inode 没变，文件内容没变，只是名字变了。

------

## 3. 创建硬链接的本质

执行：

```
ln a.txt b.txt
```

本质是在目录中新增一项：

```
a.txt -> inode 1001
b.txt -> inode 1001
```

文件没有复制，内容没有复制，只是多了一个名字。

------

# 二十、几个非常重要的例子

## 例子 1：硬链接不是复制文件

```
echo hello > a.txt
ln a.txt b.txt
```

这时：

```
ls -li
```

可能看到：

```
1001 -rw-r--r-- 2 jordan jordan 6 a.txt
1001 -rw-r--r-- 2 jordan jordan 6 b.txt
```

两个 inode 一样，说明是同一个文件。

修改：

```
echo world >> b.txt
cat a.txt
```

你会看到：

```
hello
world
```

因为 `a.txt` 和 `b.txt` 是同一个文件的两个名字。

------

## 例子 2：软链接是快捷方式

```
echo hello > a.txt
ln -s a.txt link.txt
```

查看：

```
ls -l
```

可能看到：

```
link.txt -> a.txt
```

如果删除：

```
rm a.txt
```

再执行：

```
cat link.txt
```

会失败。

因为软链接指向的目标没了。

------

## 例子 3：unlink 后文件可能还活着

程序：

```
int fd = open("a.txt", O_RDONLY);
unlink("a.txt");

/* 此时目录里已经看不到 a.txt，但 fd 仍然能读它 */

close(fd);
```

这说明：

```
文件名没了，不代表文件内容马上没了
只要还有进程打开它，它就还存在
```

------

## 例子 4：rename 可以安全替换文件

程序保存配置时：

```
先写 config.tmp
写完并确认成功
再 rename("config.tmp", "config.conf")
```

好处是：

```
不会让 config.conf 长时间处于半写入状态
```

很多可靠程序都会用这种方式。

# 二十一、这一章容易混淆的点

## 1. 文件名和文件不是一回事

文件名在目录里，文件本体由 inode 表示。

```
文件名只是入口
inode 才是文件身份
```

------

## 2. rm 删除的是文件名

`rm a.txt` 本质上类似：

```
unlink("a.txt")
```

它删除的是目录项。

------

## 3. 硬链接和软链接不一样

硬链接：

```
直接指向同一个 inode
```

软链接：

```
保存目标路径
```

------

## 4. readlink() 不自动加字符串结束符

这个是 C 编程容易出错的点。

```
ssize_t n = readlink("link.txt", buf, sizeof(buf));
buf[n] = '\0';
```

需要自己加 `\0`。

------

## 5. rmdir() 只能删除空目录

非空目录不能直接用 `rmdir()` 删除。

------

## 6. 相对路径依赖当前工作目录

```
open("a.txt", O_RDONLY);
```

打开的是当前工作目录下的 `a.txt`。

如果当前工作目录变了，打开的文件也可能变。
