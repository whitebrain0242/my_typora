下面按你的目录来讲。可以先记住一句主线：

**程序是“菜谱”，进程是“正在做菜的厨师”；信号是操作系统给进程发的“紧急通知”；信号处理器就是进程收到通知后临时执行的一段应急代码。**

# 第6章 进程

## 6.1 进程和程序

**程序**是存放在磁盘上的可执行文件，比如：

```bash
/bin/ls
./a.out
/usr/bin/python3
```

它本身是“静态”的，只是一堆机器指令和数据。

**进程**是程序运行起来之后的实例，是“动态”的。一个程序可以同时产生多个进程。

比如你同时打开两个终端，都运行：

```bash
vim test.c
```

此时磁盘上只有一个 `vim` 程序，但系统里有两个 `vim` 进程。

可以这样理解：

| 概念     | 类比           | 特点                 |
| -------- | -------------- | -------------------- |
| 程序     | 菜谱           | 静态，放在磁盘上     |
| 进程     | 正在做菜的厨师 | 动态，正在执行       |
| CPU      | 厨房灶台       | 同一时刻真正执行指令 |
| 操作系统 | 餐厅经理       | 分配资源、调度进程   |

一个进程通常包含：

1. 正在执行的程序代码；
2. 当前执行到哪一行的状态；
3. 自己的内存空间；
4. 打开的文件；
5. 进程号；
6. 父进程关系；
7. 信号处理方式；
8. 环境变量等。

重点：**程序不是进程，进程是程序运行时的实体。**

------

## 6.2 进程号和父进程号

每个进程都有一个唯一标识，叫 **进程号 PID**。

获取当前进程 PID：

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("My PID = %d\n", getpid());
    return 0;
}
```

获取父进程 PID：

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("My PID = %d\n", getpid());
    printf("Parent PID = %d\n", getppid());
    return 0;
}
```

### 什么是父进程？

一个进程通常是由另一个进程创建出来的。创建它的进程就是父进程。

比如你在 shell 中运行：

```bash
./a.out
```

那么：

```text
shell 进程
   └── ./a.out 进程
```

这里 `shell` 是父进程，`./a.out` 是子进程。

### 常见 PID

| PID          | 含义                               |
| ------------ | ---------------------------------- |
| 1            | 通常是系统初始化进程，如 `systemd` |
| 当前进程 PID | `getpid()`                         |
| 父进程 PID   | `getppid()`                        |

如果父进程结束了，子进程可能会被 PID 1 的进程接管。

------

## 6.3 进程内存布局

一个进程运行时，并不是只有代码，它有一整套内存区域。

典型布局如下：

```text
高地址
+----------------------+
| 命令行参数和环境变量 |
+----------------------+
| 栈 stack             |
| 局部变量、函数调用   |
| 向低地址增长         |
+----------------------+
|                      |
| 空闲区域             |
|                      |
+----------------------+
| 堆 heap              |
| malloc/new 动态分配  |
| 向高地址增长         |
+----------------------+
| BSS 段               |
| 未初始化的全局变量   |
+----------------------+
| 数据段 data          |
| 已初始化的全局变量   |
+----------------------+
| 文本段 text          |
| 程序代码             |
+----------------------+
低地址
```

看一个例子：

```c
#include <stdio.h>
#include <stdlib.h>

int global_init = 100;       // 数据段
int global_uninit;           // BSS 段

void func(void) {
    int local = 10;          // 栈
    int *p = malloc(sizeof(int)); // 堆
    *p = 20;

    printf("local = %d\n", local);
    printf("*p = %d\n", *p);

    free(p);
}

int main(void) {
    func();
    return 0;
}
```

### 各区域作用

#### 1. 文本段 text

存放程序指令，也就是 CPU 要执行的机器代码。

例如：

```c
printf("hello\n");
```

编译后对应的指令就在文本段里。

通常文本段是只读的，防止程序意外修改自己的代码。

------

#### 2. 数据段 data

存放**已经初始化的全局变量和静态变量**。

```c
int x = 10;
static int y = 20;
```

它们在程序启动时就有明确初值。

------

#### 3. BSS 段

存放**未初始化的全局变量和静态变量**。

```c
int a;
static int b;
```

这些变量默认初始化为 0。

虽然它们逻辑上占内存，但可执行文件里不一定真的存很多 0。系统只需要记录“这里有一块需要清零的区域”。

------

#### 4. 堆 heap

堆用于动态分配内存。

例如：

```c
int *p = malloc(sizeof(int));
```

堆的生命周期由程序员控制：

```c
malloc();  // 申请
free();    // 释放
```

如果申请后不释放，就可能造成内存泄漏。

------

#### 5. 栈 stack

栈用于函数调用、局部变量、返回地址等。

例如：

```c
void f(void) {
    int x = 10;
}
```

`x` 通常在栈上。

函数结束后，它的栈空间会自动释放。

重点区别：

| 区域   | 谁管理               | 生命周期           |
| ------ | -------------------- | ------------------ |
| 栈     | 编译器和系统自动管理 | 函数调用期间       |
| 堆     | 程序员手动管理       | `malloc` 到 `free` |
| 全局区 | 系统管理             | 整个进程运行期间   |

------

## 6.4 虚拟内存管理

现代操作系统不会让进程直接使用真实物理内存，而是给每个进程一个“假象”：**好像它自己独占了一整片连续内存空间**。

这个假象叫 **虚拟地址空间**。

比如两个进程里都可能打印出类似地址：

```c
printf("%p\n", &x);
```

它们可能看起来地址相同，但实际对应的物理内存不一定相同。

### 为什么需要虚拟内存？

有几个好处：

#### 1. 进程之间互相隔离

进程 A 不能随便访问进程 B 的内存。

这就是为什么一个普通程序不能直接偷看另一个程序的变量。

#### 2. 简化程序编写

每个进程都以为自己拥有完整地址空间，不需要关心真实物理内存在哪里。

#### 3. 支持内存保护

比如代码段只读，栈不可执行，非法访问会触发段错误：

```text
Segmentation fault
```

#### 4. 支持按需加载

程序启动时，不一定把整个程序都加载到内存。用到某一页时，再把它加载进来。

这叫 **请求分页 demand paging**。

### 页 page

虚拟内存通常按“页”管理。常见页大小是 4KB。

可以理解成：

```text
虚拟内存不是一整张大纸，而是一本书，分成很多页。
操作系统按页来管理。
```

### 地址转换

CPU 访问的是虚拟地址，硬件 MMU 和操作系统配合，把虚拟地址转换为物理地址。

```text
程序看到的地址：虚拟地址
       ↓
页表转换
       ↓
真实内存地址：物理地址
```

重点：**虚拟内存让每个进程都拥有独立、安全、连续的内存视图。**

------

## 6.5 栈和栈帧

函数调用时，系统会在栈上创建一块区域，叫 **栈帧 stack frame**。

每调用一个函数，就压入一个栈帧；函数返回，就弹出一个栈帧。

例子：

```c
#include <stdio.h>

void c(void) {
    int z = 3;
    printf("c\n");
}

void b(void) {
    int y = 2;
    c();
}

void a(void) {
    int x = 1;
    b();
}

int main(void) {
    a();
    return 0;
}
```

调用过程：

```text
main()
  调用 a()
    调用 b()
      调用 c()
```

栈大概是：

```text
高地址
+----------------+
| main 的栈帧     |
+----------------+
| a 的栈帧        |
+----------------+
| b 的栈帧        |
+----------------+
| c 的栈帧        |
+----------------+
低地址
```

当 `c()` 返回后，`c` 的栈帧销毁。

然后 `b()` 返回，`b` 的栈帧销毁。

### 栈帧里通常有什么？

一个栈帧可能包含：

1. 局部变量；
2. 函数参数；
3. 返回地址；
4. 保存的寄存器；
5. 临时数据。

### 栈溢出

如果递归太深，栈空间耗尽，就会栈溢出。

```c
void f(void) {
    f();
}

int main(void) {
    f();
    return 0;
}
```

运行后很可能：

```text
Segmentation fault
```

因为每次调用 `f()` 都要创建新栈帧，最后栈爆了。

------

## 6.6 命令行参数 argc, argv

C 程序的 `main` 可以写成：

```c
int main(int argc, char *argv[])
```

其中：

| 参数   | 含义           |
| ------ | -------------- |
| `argc` | 参数个数       |
| `argv` | 参数字符串数组 |

比如执行：

```bash
./prog hello world
```

那么：

```text
argc = 3

argv[0] = "./prog"
argv[1] = "hello"
argv[2] = "world"
argv[3] = NULL
```

注意：`argv[0]` 通常是程序名。

例子：

```c
#include <stdio.h>

int main(int argc, char *argv[]) {
    for (int i = 0; i < argc; i++) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }

    return 0;
}
```

运行：

```bash
./prog one two three
```

输出：

```text
argv[0] = ./prog
argv[1] = one
argv[2] = two
argv[3] = three
```

命令行参数本质上是：**启动程序时，外部传给程序的一组字符串。**

## 6.7 环境列表

环境变量是操作系统传给进程的一组字符串，形式通常是：

```text
NAME=value
```

比如：

```text
PATH=/usr/bin:/bin
HOME=/home/user
SHELL=/bin/bash
```

### 查看环境变量

在 shell 中：

```bash
env
```

或者：

```bash
echo $PATH
```

### C 程序访问环境变量

使用 `getenv()`：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    char *home = getenv("HOME");

    if (home != NULL) {
        printf("HOME = %s\n", home);
    }

    return 0;
}
```

### 环境变量有什么用？

比如 `PATH` 决定 shell 去哪里找命令。

你输入：

```bash
ls
```

系统会在 `PATH` 中列出的目录里找 `ls`。

### 修改环境变量

```c
#include <stdlib.h>

setenv("MYVAR", "hello", 1);
unsetenv("MYVAR");
```

`setenv` 的第三个参数表示是否覆盖旧值：

```c
setenv("MYVAR", "hello", 1);
```

`1` 表示如果已经存在，也覆盖。

重点：**环境变量是进程启动时继承而来的配置信息。**

## 6.8 执行非局部跳转：setjmp() 和 longjmp()

普通 `goto` 只能在一个函数内部跳转。

但 `setjmp()` 和 `longjmp()` 可以跨函数跳转，叫 **非局部跳转**。

它有点像：“从很深的函数调用中，直接跳回之前保存的位置”。

### 基本形式

```c
#include <stdio.h>
#include <setjmp.h>

static jmp_buf env;

void f2(void) {
    printf("In f2, jump back\n");
    longjmp(env, 1);
}

void f1(void) {
    printf("In f1\n");
    f2();
}

int main(void) {
    int ret = setjmp(env);

    if (ret == 0) {
        printf("First time through setjmp\n");
        f1();
    } else {
        printf("Back from longjmp, ret = %d\n", ret);
    }

    return 0;
}
```

输出大概是：

```text
First time through setjmp
In f1
In f2, jump back
Back from longjmp, ret = 1
```

### 怎么理解？

第一次执行：

```c
setjmp(env)
```

它保存当前执行环境，并返回 0。

后来执行：

```c
longjmp(env, 1)
```

程序会跳回 `setjmp()` 那里，并让 `setjmp()` 返回 1。

所以 `setjmp()` 很特殊：**它可能返回两次**。

第一次正常返回 0，第二次被 `longjmp()` 跳回来，返回非 0。

### 用途

常见用途：

1. 错误恢复；
2. 从深层函数中快速退出；
3. 简单异常处理机制；
4. 信号处理器中跳出危险执行流。

### 注意

`setjmp/longjmp` 很强，但也容易破坏程序结构。

例如：

```text
main -> a -> b -> c
```

如果在 `c` 里直接 `longjmp` 回 `main`，那么 `a`、`b`、`c` 的正常返回流程都被跳过了。

所以它像“安全出口”，不是普通走廊。能不用就不用，必须用时要非常小心。

------

## 6.9 第6章总结

第6章核心是：**进程是程序运行时的实体。**

重点记忆：

1. 程序是静态文件，进程是运行中的程序。
2. 每个进程有 PID，父进程有 PPID。
3. 进程有独立虚拟地址空间。
4. 典型内存布局包括 text、data、BSS、heap、stack。
5. 栈用于函数调用，堆用于动态内存分配。
6. `argc/argv` 是命令行参数。
7. 环境变量是进程继承来的配置信息。
8. `setjmp/longjmp` 可以跨函数跳转，但要谨慎使用。

# 第20章 信号：基本概念

## 20.1 概念和概述

**信号 signal** 是一种通知机制。

可以理解成：操作系统或其他进程给当前进程发了一个“提醒”或“打断”。

比如：

你在终端运行一个程序：

```bash
./prog
```

按下：

```text
Ctrl + C
```

终端会给前台进程发送 `SIGINT` 信号，意思是：“请中断运行”。

再比如：

```bash
kill 1234
```

默认发送 `SIGTERM` 给 PID 为 1234 的进程，意思是：“请终止”。

### 信号有什么特点？

信号是异步的。

也就是说，进程不知道什么时候会收到信号。

程序可能正在执行：

```c
x = x + 1;
```

突然信号来了，操作系统就打断当前执行，转去执行信号处理器。

### 信号来源

信号可以来自：

1. 用户键盘输入；
2. 操作系统异常；
3. 其他进程；
4. 进程自己；
5. 定时器；
6. 子进程状态变化。

例子：

| 行为                 | 产生的信号 |
| -------------------- | ---------- |
| Ctrl+C               | `SIGINT`   |
| Ctrl+\               | `SIGQUIT`  |
| 访问非法内存         | `SIGSEGV`  |
| 除以 0               | `SIGFPE`   |
| 子进程结束           | `SIGCHLD`  |
| 管道读端关闭后写管道 | `SIGPIPE`  |

------

## 20.2 信号类型和默认行为

每种信号都有编号和名字。

常见信号：

| 信号      | 含义                  | 默认行为        |
| --------- | --------------------- | --------------- |
| `SIGINT`  | 终端中断，通常 Ctrl+C | 终止进程        |
| `SIGTERM` | 请求终止              | 终止进程        |
| `SIGKILL` | 强制杀死              | 终止进程        |
| `SIGSEGV` | 非法内存访问          | 终止并产生 core |
| `SIGCHLD` | 子进程状态改变        | 默认忽略        |
| `SIGSTOP` | 暂停进程              | 暂停            |
| `SIGCONT` | 继续进程              | 继续            |
| `SIGALRM` | 定时器到期            | 终止进程        |
| `SIGPIPE` | 管道破裂              | 终止进程        |

### 默认行为大致分几类

| 默认行为 | 含义                 |
| -------- | -------------------- |
| Term     | 终止进程             |
| Core     | 终止并生成 core dump |
| Ign      | 忽略                 |
| Stop     | 暂停进程             |
| Cont     | 继续进程             |

### 特别重要

`SIGKILL` 和 `SIGSTOP` 不能被捕获、不能被忽略、不能被阻塞。

也就是说：

```text
SIGKILL：必须死
SIGSTOP：必须停
```

它们是操作系统保留的强制控制手段。

------

## 20.3 改变信号处置：signal()

进程收到信号时，可以有三种处理方式：

1. 执行默认动作；
2. 忽略信号；
3. 捕获信号，执行自定义处理函数。

使用 `signal()` 可以改变信号处置方式。

例子：捕获 Ctrl+C。

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handler(int sig) {
    printf("Caught signal %d\n", sig);
}

int main(void) {
    signal(SIGINT, handler);

    while (1) {
        printf("Running...\n");
        sleep(1);
    }

    return 0;
}
```

运行后按 Ctrl+C，程序不会立刻退出，而是执行：

```text
Caught signal 2
```

### 忽略信号

```c
signal(SIGINT, SIG_IGN);
```

这样 Ctrl+C 就会被忽略。

### 恢复默认行为

```c
signal(SIGINT, SIG_DFL);
```

不过实际编程中，更推荐使用 `sigaction()`，因为它行为更可靠、更可控。

------

## 20.4 信号处理器简介

信号处理器就是收到某个信号时自动执行的函数。

形式通常是：

```c
void handler(int sig);
```

例子：

```c
void handler(int sig) {
    printf("Received signal: %d\n", sig);
}
```

当信号到达时，流程大概是：

```text
程序正常执行
    ↓
信号到达
    ↓
暂停当前代码
    ↓
执行 signal handler
    ↓
handler 返回
    ↓
继续原来的代码
```

它像是程序执行过程中突然插入的一段代码。

但注意：信号处理器非常特殊，不能随便写复杂逻辑。比如在处理器里调用 `printf()` 通常不安全，后面第21章会重点讲。

------

## 20.5 发送信号：kill()

虽然名字叫 `kill()`，但它不一定是杀死进程。它的本质是：

**向某个进程发送信号。**

函数原型：

```c
#include <signal.h>

int kill(pid_t pid, int sig);
```

例子：

```c
kill(1234, SIGTERM);
```

意思是给 PID 为 1234 的进程发送 `SIGTERM`。

### shell 中的 kill

```bash
kill 1234
```

默认发送 `SIGTERM`。

```bash
kill -9 1234
```

发送 `SIGKILL`。

```bash
kill -INT 1234
```

发送 `SIGINT`。

### C 语言例子

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

int main(void) {
    pid_t pid = 1234;

    if (kill(pid, SIGTERM) == -1) {
        perror("kill");
    }

    return 0;
}
```

------

## 20.6 检查进程的存在

`kill(pid, 0)` 有一个特殊用途：不发送真正的信号，只检查进程是否存在以及是否有权限。

```c
if (kill(pid, 0) == 0) {
    printf("Process exists and we can signal it\n");
} else {
    perror("kill");
}
```

可能结果：

| 情况             | 含义                         |
| ---------------- | ---------------------------- |
| 返回 0           | 进程存在，并且有权限发送信号 |
| `errno == ESRCH` | 进程不存在                   |
| `errno == EPERM` | 进程存在，但没有权限         |

所以 `kill(pid, 0)` 常用于检查某个进程是否还活着。

------

## 20.7 发送信号的其他方式：raise() 和 killpg()

### raise()

`raise()` 给当前进程自己发送信号。

```c
#include <signal.h>

raise(SIGINT);
```

大致等价于：

```c
kill(getpid(), SIGINT);
```

例子：

```c
#include <stdio.h>
#include <signal.h>

int main(void) {
    printf("Send SIGTERM to myself\n");
    raise(SIGTERM);
    printf("This may not be printed\n");
    return 0;
}
```

默认情况下，`SIGTERM` 会终止进程，所以后面的输出通常不会出现。

------

### killpg()

`killpg()` 给一个进程组发送信号。

```c
killpg(pgrp, sig);
```

进程组常用于 shell 作业控制。

比如你运行：

```bash
sleep 100 | cat
```

这是一个管道，里面可能有多个进程。终端按 Ctrl+C 时，通常不是只杀一个进程，而是给前台进程组发 `SIGINT`。

------

## 20.8 显示信号描述

可以用 `strsignal()` 获取信号描述字符串。

```c
#include <stdio.h>
#include <string.h>
#include <signal.h>

int main(void) {
    printf("%s\n", strsignal(SIGINT));
    return 0;
}
```

可能输出：

```text
Interrupt
```

也可以用 `psignal()`：

```c
#include <signal.h>

psignal(SIGTERM, "Signal received");
```

可能输出：

```text
Signal received: Terminated
```

这些函数主要用于调试和打印错误信息。

------

## 20.9 信号集

**信号集 signal set** 是一组信号的集合。

比如：

```text
{ SIGINT, SIGTERM, SIGQUIT }
```

在 C 中用 `sigset_t` 表示。

常用函数：

```c
sigemptyset(&set);        // 清空集合
sigfillset(&set);         // 填满集合
sigaddset(&set, SIGINT);  // 添加信号
sigdelset(&set, SIGINT);  // 删除信号
sigismember(&set, SIGINT);// 判断是否在集合中
```

例子：

```c
#include <stdio.h>
#include <signal.h>

int main(void) {
    sigset_t set;

    sigemptyset(&set);
    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);

    if (sigismember(&set, SIGINT)) {
        printf("SIGINT is in set\n");
    }

    return 0;
}
```

信号集主要用于：

1. 设置信号掩码；
2. 查看等待信号；
3. 配置 `sigaction()`。

------

## 20.10 信号掩码：阻塞信号传递

每个进程都有一个 **信号掩码 signal mask**。

信号掩码决定：哪些信号当前被阻塞。

被阻塞不是丢弃，而是暂时不递送。

类比：

```text
你正在开会，不接电话。
电话不是没打来，而是先挂在未接来电里。
等会议结束，再处理。
```

### 阻塞 SIGINT

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

int main(void) {
    sigset_t blockSet;

    sigemptyset(&blockSet);
    sigaddset(&blockSet, SIGINT);

    sigprocmask(SIG_BLOCK, &blockSet, NULL);

    printf("SIGINT blocked. Press Ctrl+C now.\n");
    sleep(10);

    printf("Unblocking SIGINT now.\n");
    sigprocmask(SIG_UNBLOCK, &blockSet, NULL);

    sleep(3);
    return 0;
}
```

运行后，在前 10 秒按 Ctrl+C，程序不会马上退出。等解除阻塞后，之前的 `SIGINT` 才可能被递送。

### sigprocmask 的常见用法

```c
sigprocmask(SIG_BLOCK, &set, &oldset);
```

阻塞 `set` 中的信号，并保存旧掩码到 `oldset`。

```c
sigprocmask(SIG_UNBLOCK, &set, NULL);
```

解除阻塞。

```c
sigprocmask(SIG_SETMASK, &set, NULL);
```

直接把信号掩码设置成 `set`。

------

## 20.11 处于等待状态的信号

如果一个信号来了，但它当前被阻塞，那么它就进入 **pending 等待状态**。

可以用 `sigpending()` 查看当前等待信号。

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

int main(void) {
    sigset_t blockSet, pendingSet;

    sigemptyset(&blockSet);
    sigaddset(&blockSet, SIGINT);

    sigprocmask(SIG_BLOCK, &blockSet, NULL);

    printf("SIGINT blocked. Press Ctrl+C within 5 seconds.\n");
    sleep(5);

    sigpending(&pendingSet);

    if (sigismember(&pendingSet, SIGINT)) {
        printf("SIGINT is pending\n");
    }

    sigprocmask(SIG_UNBLOCK, &blockSet, NULL);

    return 0;
}
```

如果你在 5 秒内按了 Ctrl+C，解除阻塞后，信号会被处理。

------

## 20.12 不对信号进行排队处理

传统信号，也叫标准信号，通常**不排队**。

意思是：同一个信号在阻塞期间来了多次，系统通常只记一次。

比如：

```text
SIGINT 被阻塞期间，你按了 5 次 Ctrl+C。
```

解除阻塞后，程序通常只收到一次 `SIGINT`。

类比：

```text
门铃响了 5 次。
你只知道“有人按过门铃”，但不一定知道按了几次。
```

这就是信号的非队列化。

注意：实时信号通常可以排队，但传统信号一般不排队。你这里第20章重点通常是传统信号，所以要记住：**普通信号不适合用来精确计数事件次数。**

------

## 20.13 改变信号处置：sigaction()

`sigaction()` 是比 `signal()` 更推荐的信号处理方式。

函数大致用法：

```c
#include <signal.h>

int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);
```

例子：

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handler(int sig) {
    write(STDOUT_FILENO, "Caught SIGINT\n", 14);
}

int main(void) {
    struct sigaction sa;

    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);

    while (1) {
        pause();
    }

    return 0;
}
```

### struct sigaction 重要字段

```c
struct sigaction {
    void (*sa_handler)(int);
    sigset_t sa_mask;
    int sa_flags;
};
```

#### sa_handler

指定信号处理函数：

```c
sa.sa_handler = handler;
```

也可以设置为：

```c
sa.sa_handler = SIG_IGN; // 忽略
sa.sa_handler = SIG_DFL; // 默认
```

#### sa_mask

表示执行该信号处理器期间，还要额外阻塞哪些信号。

例如处理 `SIGINT` 时，不希望 `SIGTERM` 打断它，就可以把 `SIGTERM` 加入 `sa_mask`。

#### sa_flags

控制额外行为。

常见选项：

| 标志           | 含义                             |
| -------------- | -------------------------------- |
| `SA_RESTART`   | 某些被信号中断的系统调用自动重启 |
| `SA_SIGINFO`   | 使用高级信号处理函数             |
| `SA_NODEFER`   | 处理当前信号时不自动阻塞同类信号 |
| `SA_RESETHAND` | 处理一次后恢复默认处理           |

重点：实际开发中优先用 `sigaction()`，少用老式 `signal()`。

------

## 20.14 等待信号：pause()

`pause()` 会让进程暂停执行，直到收到一个信号。

```c
#include <unistd.h>

int pause(void);
```

例子：

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handler(int sig) {
    write(STDOUT_FILENO, "Signal caught\n", 14);
}

int main(void) {
    struct sigaction sa;

    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);

    printf("Waiting for signal. Press Ctrl+C.\n");

    pause();

    printf("pause returned\n");

    return 0;
}
```

流程：

```text
程序执行 pause()
    ↓
睡眠等待信号
    ↓
按 Ctrl+C
    ↓
执行 handler
    ↓
pause 返回
```

注意：`pause()` 只有在信号处理器执行并返回后才返回，并且通常返回 `-1`，`errno` 设置为 `EINTR`。

------

## 20.15 第20章总结

第20章核心是：**信号是异步通知机制。**

重点记忆：

1. 信号用于通知进程发生了某件事。
2. Ctrl+C 会产生 `SIGINT`。
3. `kill()` 本质是发送信号，不一定杀死进程。
4. `SIGKILL` 和 `SIGSTOP` 不能捕获、不能忽略、不能阻塞。
5. 进程可以默认处理、忽略或捕获信号。
6. `signal()` 能设置信号处理，但推荐 `sigaction()`。
7. 信号集 `sigset_t` 表示一组信号。
8. 信号掩码可以暂时阻塞信号。
9. 被阻塞的信号会处于 pending 状态。
10. 标准信号通常不排队，同类信号来了多次可能只记一次。
11. `pause()` 可以等待信号到达。

------

# 第21章 信号：信号处理器函数

第21章比第20章更重要的一点是：**信号处理器不能像普通函数一样随便写。**

因为它是在程序任意位置突然插进来的。

------

## 21.1 设计信号处理器函数

信号处理器要遵守几个原则：

1. 尽量短；
2. 尽量简单；
3. 尽量只设置标志位；
4. 不调用不安全函数；
5. 小心全局变量；
6. 必要时保存和恢复 `errno`。

错误示范：

```c
void handler(int sig) {
    printf("Signal caught\n");
    malloc(100);
    exit(1);
}
```

这看起来很正常，但在信号处理器里可能有问题。

因为 `printf()`、`malloc()` 这些函数内部状态复杂，可能不是异步信号安全的。

更安全的写法：

```c
#include <signal.h>
#include <unistd.h>

volatile sig_atomic_t gotSigint = 0;

void handler(int sig) {
    gotSigint = 1;
}

int main(void) {
    struct sigaction sa;

    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);

    while (!gotSigint) {
        // 主循环
    }

    write(STDOUT_FILENO, "SIGINT received\n", 16);

    return 0;
}
```

这里处理器只做一件事：

```c
gotSigint = 1;
```

真正复杂的逻辑放回主程序中执行。

------

## 21.1.1 再论信号的非队列化处理

第20章说过：标准信号通常不排队。

现在结合信号处理器来看一个问题。

假设程序这样写：

```c
volatile sig_atomic_t count = 0;

void handler(int sig) {
    count++;
}
```

你可能以为每收到一个信号，`count` 就加 1。

但如果信号被阻塞期间来了 10 次，最后可能只处理 1 次。

所以 `count` 不一定等于真实发生次数。

### 重点

普通信号适合表达：

```text
某件事发生了
```

不适合表达：

```text
某件事发生了 N 次
```

例如：

| 场景                 | 普通信号是否适合 |
| -------------------- | ---------------- |
| 通知程序退出         | 适合             |
| 通知配置文件需要重载 | 适合             |
| 精确统计事件次数     | 不适合           |

如果需要可靠计数，可以考虑管道、消息队列、eventfd、实时信号等机制。

------

## 21.1.2 可重入函数和异步信号安全函数

这是第21章的难点。

### 什么是可重入？

一个函数执行到一半时，如果又被再次调用，不会出错，这种函数叫 **可重入函数 reentrant function**。

举个简单类比：

你正在写一个共享笔记本：

```text
步骤1：翻到最后一页
步骤2：写一行
步骤3：更新目录
```

如果你写到步骤2时，突然有人打断你，又让你从头执行一遍写笔记的流程，就可能把笔记本状态弄乱。

很多库函数内部有全局状态或静态缓冲区，因此不是可重入的。

### printf 为什么危险？

假设主程序正在执行：

```c
printf("hello");
```

`printf()` 内部可能正在操作缓冲区。

这时信号来了，handler 里面又调用：

```c
printf("signal");
```

就可能导致内部缓冲区状态混乱。

所以在信号处理器里不要随便调用 `printf()`。

### 异步信号安全函数

异步信号安全函数是指：可以安全地在信号处理器中调用的函数。

常见相对安全的函数包括：

```c
write()
_exit()
sigaction()
sigprocmask()
kill()
getpid()
```

例如在 handler 中更推荐：

```c
write(STDOUT_FILENO, "Signal\n", 7);
```

而不是：

```c
printf("Signal\n");
```

### handler 中常见安全策略

推荐这样：

```c
volatile sig_atomic_t flag = 0;

void handler(int sig) {
    flag = 1;
}
```

然后主循环里：

```c
if (flag) {
    // 执行复杂逻辑
}
```

这叫“处理器只打标记，主程序做事情”。

------

## 21.1.3 全局变量和 sig_atomic_t 数据类型

信号处理器和主程序之间经常需要共享变量。

普通写法可能有问题：

```c
int flag = 0;

void handler(int sig) {
    flag = 1;
}
```

编译器可能优化主循环：

```c
while (!flag) {
}
```

它可能认为 `flag` 没有变化，于是一直不重新读取。

所以应该写：

```c
volatile sig_atomic_t flag = 0;
```

### volatile 的作用

告诉编译器：

```text
这个变量可能在你看不见的地方被修改，不要乱优化。
```

### sig_atomic_t 的作用

保证对这个类型的读写是原子的。

也就是说，读写不会被中断到一半。

推荐模式：

```c
#include <signal.h>

volatile sig_atomic_t gotSignal = 0;

void handler(int sig) {
    gotSignal = 1;
}
```

注意：`sig_atomic_t` 适合做简单标志，不适合存复杂数据结构。

------

## 21.2 终止信号处理器函数的其他方法

信号处理器通常是执行完后返回，程序继续原来的执行位置。

普通流程：

```text
主程序执行
    ↓
信号到达
    ↓
handler 执行
    ↓
handler 返回
    ↓
主程序继续
```

但也有其他方式：

1. 在 handler 中调用 `_exit()` 直接退出；
2. 在 handler 中调用 `longjmp()` 跳转；
3. 调用 `abort()` 异常终止；
4. 信号处理器导致另一个致命信号。

这些方式都需要谨慎。

------

## 21.2.1 在信号处理器函数中执行非本地跳转

可以在信号处理器中用 `siglongjmp()` 跳回主程序某处。

更推荐使用：

```c
sigsetjmp()
siglongjmp()
```

而不是普通的：

```c
setjmp()
longjmp()
```

因为信号处理还涉及信号掩码，`sigsetjmp()` 可以选择保存信号掩码。

例子：

```c
#include <stdio.h>
#include <signal.h>
#include <setjmp.h>
#include <unistd.h>

static sigjmp_buf env;

void handler(int sig) {
    siglongjmp(env, 1);
}

int main(void) {
    struct sigaction sa;

    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);

    if (sigsetjmp(env, 1) == 0) {
        printf("Press Ctrl+C to jump back\n");

        while (1) {
            sleep(1);
        }
    } else {
        printf("Returned from signal handler by siglongjmp\n");
    }

    return 0;
}
```

### 注意风险

从信号处理器里跳走很危险，因为被打断的代码可能正处于不完整状态。

例如主程序正在：

```c
malloc()
```

中间被信号打断，handler 直接 `siglongjmp()` 跳走，可能导致库内部状态混乱。

所以这种技术只适合特殊场景。

------

## 21.2.2 异常终止进程：abort()

`abort()` 用于让进程异常终止。

```c
#include <stdlib.h>

abort();
```

它通常会产生 `SIGABRT` 信号。

默认行为是：

```text
终止进程，并可能生成 core dump
```

### abort 和 exit 的区别

| 函数      | 含义                                            |
| --------- | ----------------------------------------------- |
| `exit()`  | 正常退出，会调用退出处理函数，刷新 stdio 缓冲区 |
| `_exit()` | 立即退出，不做标准清理                          |
| `abort()` | 异常终止，通常产生 core dump                    |

例子：

```c
#include <stdlib.h>

int main(void) {
    abort();
}
```

常用于：

1. 程序发现严重内部错误；
2. 断言失败；
3. 调试时保留 core dump。

例如：

```c
#include <assert.h>

int main(void) {
    int x = 0;
    assert(x != 0);
    return 0;
}
```

断言失败通常会触发异常终止。

------

## 21.3 在备选栈中处理信号：sigaltstack()

正常情况下，信号处理器也在当前进程的普通栈上运行。

但如果普通栈坏了或满了怎么办？

比如栈溢出时产生 `SIGSEGV`，而处理 `SIGSEGV` 又需要使用栈。如果普通栈已经不能用了，handler 可能也跑不起来。

这时可以用 **备选信号栈 alternate signal stack**。

### sigaltstack 的作用

提前准备一块备用栈：

```text
普通栈坏了？
没关系，用备用栈来执行信号处理器。
```

典型场景：

1. 捕获栈溢出；
2. 处理严重内存错误；
3. 编写底层运行时或调试工具。

### 大致步骤

1. 分配一块内存作为备用栈；
2. 用 `sigaltstack()` 注册；
3. 用 `sigaction()` 设置 `SA_ONSTACK`；
4. 信号到来时，handler 在备用栈执行。

简化示意：

```c
stack_t ss;
ss.ss_sp = malloc(SIGSTKSZ);
ss.ss_size = SIGSTKSZ;
ss.ss_flags = 0;

sigaltstack(&ss, NULL);

struct sigaction sa;
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_ONSTACK;

sigaction(SIGSEGV, &sa, NULL);
```

重点：普通应用很少直接用，但理解它能帮助你明白：**信号处理器本身也需要栈空间。**

------

## 21.4 SA_SIGINFO 标志

普通信号处理器只能收到一个参数：

```c
void handler(int sig);
```

只能知道“来了哪个信号”。

如果想知道更多信息，比如：

1. 谁发送的信号；
2. 信号携带的附加数据；
3. 出错地址；
4. 子进程状态；

可以使用 `SA_SIGINFO`。

这时处理器形式变成：

```c
void handler(int sig, siginfo_t *info, void *ucontext);
```

例子：

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void handler(int sig, siginfo_t *info, void *ucontext) {
    char buf[100];
    int len = snprintf(buf, sizeof(buf),
                       "Signal %d from PID %d\n",
                       sig, info->si_pid);
    write(STDOUT_FILENO, buf, len);
}

int main(void) {
    struct sigaction sa;

    sa.sa_sigaction = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_SIGINFO;

    sigaction(SIGUSR1, &sa, NULL);

    printf("PID = %d\n", getpid());

    while (1) {
        pause();
    }

    return 0;
}
```

然后另一个终端发送：

```bash
kill -USR1 <pid>
```

handler 可以知道发送者 PID。

### siginfo_t 常见字段

| 字段       | 含义                                 |
| ---------- | ------------------------------------ |
| `si_signo` | 信号编号                             |
| `si_code`  | 信号产生原因                         |
| `si_pid`   | 发送信号的进程 PID                   |
| `si_uid`   | 发送者用户 ID                        |
| `si_addr`  | 导致错误的内存地址，常见于 `SIGSEGV` |

------

## 21.5 系统调用的中断和重启

这是信号编程里非常实际的问题。

假设程序正在阻塞等待输入：

```c
read(fd, buf, size);
```

这时信号来了。

会发生什么？

可能有两种情况：

1. `read()` 被中断，返回 `-1`，`errno = EINTR`；
2. 系统自动重启 `read()`，好像没发生过中断。

是否自动重启，和系统调用类型、信号配置、`SA_RESTART` 有关。

### 例子

```c
ssize_t n = read(fd, buf, sizeof(buf));

if (n == -1) {
    if (errno == EINTR) {
        // 被信号中断
    } else {
        // 真正错误
    }
}
```

### 为什么要处理 EINTR？

因为信号是异步的，你不知道它什么时候来。

如果你写：

```c
n = read(fd, buf, size);
if (n == -1) {
    perror("read");
    exit(1);
}
```

那么当 `read()` 只是被信号打断时，你可能误以为发生了严重错误。

更稳妥写法：

```c
ssize_t n;

while ((n = read(fd, buf, size)) == -1 && errno == EINTR) {
    continue;
}
```

意思是：

```text
如果只是被信号中断，就重新读。
```

### SA_RESTART

使用 `sigaction()` 时可以设置：

```c
sa.sa_flags = SA_RESTART;
```

这会让某些被信号中断的系统调用自动重启。

但不是所有系统调用都会重启，所以仍然要理解 `EINTR`。

重点：**写健壮的系统程序时，要考虑系统调用被信号中断。**

------

## 21.6 第21章总结

第21章核心是：**信号处理器必须写得非常谨慎。**

重点记忆：

1. 信号处理器是异步执行的，可能在程序任意位置插入。
2. handler 要短小，最好只设置标志位。
3. 不要在 handler 中随便调用 `printf()`、`malloc()` 等不安全函数。
4. 可以使用 `write()` 这类异步信号安全函数。
5. 主程序和 handler 共享变量时，推荐使用 `volatile sig_atomic_t`。
6. 标准信号不排队，不适合精确计数。
7. 在 handler 中使用 `siglongjmp()` 要非常小心。
8. `abort()` 用于异常终止进程。
9. `sigaltstack()` 可以让信号处理器在备用栈上运行。
10. `SA_SIGINFO` 可以获得更丰富的信号信息。
11. 系统调用可能因信号中断，返回 `EINTR`。
12. `SA_RESTART` 可以让某些系统调用自动重启。

# 一个完整小例子：优雅退出程序

这个例子能串起很多知识点。

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

volatile sig_atomic_t stop = 0;

void handler(int sig) {
    stop = 1;
}

int main(int argc, char *argv[]) {
    struct sigaction sa;

    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGINT, &sa, NULL);
    sigaction(SIGTERM, &sa, NULL);

    printf("PID = %d\n", getpid());
    printf("Press Ctrl+C to stop\n");

    while (!stop) {
        printf("Working...\n");
        sleep(1);
    }

    printf("Gracefully exiting...\n");

    return 0;
}
```

运行：

```bash
./prog
```

输出：

```text
PID = 12345
Press Ctrl+C to stop
Working...
Working...
```

按 Ctrl+C 后：

```text
Gracefully exiting...
```

这个程序体现了：

1. `getpid()` 获取进程号；
2. `sigaction()` 注册信号处理器；
3. `SIGINT` 来自 Ctrl+C；
4. handler 只设置 `stop = 1`；
5. 主循环检测标志后优雅退出；
6. 使用 `volatile sig_atomic_t` 保证安全。

## 这就是信号编程中非常经典的写法。
