# 练习 1：观察 fork() 一次调用，两次返回

## 目标

理解：

```text
fork() 调用一次，但父进程和子进程都会从 fork() 后面继续执行。
父进程中 fork() 返回子进程 PID。
子进程中 fork() 返回 0。
```

------

## 示例代码：`fork_basic.c`

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>

int main(void) {
    printf("Before fork: current PID = %ld\n", (long)getpid());

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("Child process:\n");
        printf("  fork() returned: %ld\n", (long)pid);
        printf("  child PID:       %ld\n", (long)getpid());
        printf("  parent PID:      %ld\n", (long)getppid());
    } else {
        printf("Parent process:\n");
        printf("  fork() returned child PID: %ld\n", (long)pid);
        printf("  parent PID:               %ld\n", (long)getpid());
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_basic.c -o fork_basic
./fork_basic
```

------

## 你应该观察什么？

你大概率会看到类似输出： 

```text
Before fork: current PID = 12345
Parent process:
  fork() returned child PID: 12346
  parent PID:               12345
Child process:
  fork() returned: 0
  child PID:       12346
  parent PID:      12345
```

但父进程和子进程的输出顺序不一定固定。

------

## 通俗解释

可以这样想：

```text
fork() 就像把当前进程复制了一份。
复制完成后，父进程和子进程都站在 fork() 后面继续往下执行。
```

区别是：

```text
父进程拿到子进程的 PID。
子进程拿到 0。
```

所以你才能用：

```c
if (pid == 0) {
    // 子进程
} else {
    // 父进程
}
```

来区分父子进程。

# 练习 2：验证 fork() 后父子进程内存相互独立

## 目标

理解：

```text
fork() 后，父子进程的变量看起来一开始一样。
但之后各自修改变量，不会互相影响。
```

------

## 示例代码：`fork_memory.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int global_var = 100;

int main(void) {
    int local_var = 200;
    int *heap_var = malloc(sizeof(int));

    if (heap_var == NULL) {
        perror("malloc");
        return 1;
    }

    *heap_var = 300;

    printf("Before fork:\n");
    printf("  global_var = %d\n", global_var);
    printf("  local_var  = %d\n", local_var);
    printf("  heap_var   = %d\n", *heap_var);

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        free(heap_var);
        return 1;
    }

    if (pid == 0) {
        global_var = 111;
        local_var = 222;
        *heap_var = 333;

        printf("\nChild changed values:\n");
        printf("  global_var = %d\n", global_var);
        printf("  local_var  = %d\n", local_var);
        printf("  heap_var   = %d\n", *heap_var);

        free(heap_var);
        _exit(0);
    } else {
        waitpid(pid, NULL, 0);

        printf("\nParent after child exits:\n");
        printf("  global_var = %d\n", global_var);
        printf("  local_var  = %d\n", local_var);
        printf("  heap_var   = %d\n", *heap_var);

        free(heap_var);
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_memory.c -o fork_memory
./fork_memory
```

------

## 你应该观察什么？

子进程里变量变了：

```text
Child changed values:
  global_var = 111
  local_var  = 222
  heap_var   = 333
```

但父进程里还是原来的：

```text
Parent after child exits:
  global_var = 100
  local_var  = 200
  heap_var   = 300
```

------

## 通俗解释

`fork()` 后，父子进程的内存逻辑上是独立的。

可以想象：

```text
父进程有一本笔记本。
fork() 后，子进程拿到了一本内容一模一样的复印本。
之后孩子在自己的本子上改内容，不会影响父亲的本子。
```

现代 Linux 实际上会使用写时复制，也就是 Copy-On-Write。

意思是：

```text
刚 fork() 时，内核不会马上复制全部内存。
只有当父进程或子进程要修改某一页内存时，内核才真正复制那一页。
```

所以你看到的效果是：

```text
父子进程变量互不影响。
```

# 练习 3：验证 fork() 后父子进程共享打开文件的偏移量

## 目标

理解：

```text
fork() 后，父子进程各自有文件描述符表。
但是它们的文件描述符指向同一个打开文件对象。
所以文件偏移量是共享的。
```

------

## 示例代码：`fork_file_offset.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/wait.h>

int main(void) {
    int fd = open("shared_offset.txt", O_CREAT | O_TRUNC | O_RDWR, 0644);

    if (fd == -1) {
        perror("open");
        return 1;
    }

    write(fd, "PARENT-BEFORE\n", 14);

    printf("Parent before fork: file offset = %lld\n",
           (long long)lseek(fd, 0, SEEK_CUR));

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        close(fd);
        return 1;
    }

    if (pid == 0) {
        printf("Child starts: file offset = %lld\n",
               (long long)lseek(fd, 0, SEEK_CUR));

        write(fd, "CHILD-WRITE\n", 12);

        printf("Child after write: file offset = %lld\n",
               (long long)lseek(fd, 0, SEEK_CUR));

        close(fd);
        _exit(0);
    } else {
        waitpid(pid, NULL, 0);

        printf("Parent after child exits: file offset = %lld\n",
               (long long)lseek(fd, 0, SEEK_CUR));

        write(fd, "PARENT-AFTER\n", 13);

        close(fd);
    }

    printf("\nNow run:\n");
    printf("  cat shared_offset.txt\n");

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_file_offset.c -o fork_file_offset
./fork_file_offset
cat shared_offset.txt
```

------

## 你应该观察什么？

文件内容大概是：

```text
PARENT-BEFORE
CHILD-WRITE
PARENT-AFTER
```

而且父进程在子进程写完之后看到的文件偏移量已经变大了。

------

## 通俗解释

这不是说父子进程共享所有东西。

准确说：

```text
父进程有自己的文件描述符表。
子进程也有自己的文件描述符表。
但两个 fd 指向同一个“打开文件对象”。
```

这个打开文件对象里包含：

```text
文件当前位置，也就是 offset
打开状态标志，例如 O_APPEND
```

所以：

```text
子进程写文件会移动 offset。
父进程随后看到的 offset 也变了。
```

类比一下：

```text
父子各自手里有一支笔，
但他们在同一本本子上接着写。
```

# 练习 4：观察 fork() 后父子进程的竞争条件

## 目标

理解：

```text
fork() 后，父进程和子进程谁先运行是不确定的。
程序不应该依赖“父进程一定先执行”或“子进程一定先执行”。
```

------

## 示例代码：`fork_race.c`

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

int main(void) {
    setbuf(stdout, NULL);

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        for (int i = 0; i < 5; i++) {
            printf("Child:  i = %d\n", i);
            usleep(100000);
        }
        _exit(0);
    } else {
        for (int i = 0; i < 5; i++) {
            printf("Parent: i = %d\n", i);
            usleep(100000);
        }

        waitpid(pid, NULL, 0);
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_race.c -o fork_race
./fork_race
./fork_race
./fork_race
```

------

## 你应该观察什么？

多运行几次，输出顺序可能不同。

比如一次是：

```text
Parent: i = 0
Child:  i = 0
Parent: i = 1
Child:  i = 1
```

另一次可能是：

```text
Child:  i = 0
Parent: i = 0
Child:  i = 1
Parent: i = 1
```

------

## 通俗解释

父进程和子进程都是独立的进程。

它们谁先执行，由 Linux 调度器决定。

所以：

```text
fork() 之后，执行顺序是不可靠的。
```

如果你的程序逻辑要求：

```text
子进程必须先执行某件事，
父进程才能继续。
```

那就必须使用同步机制，例如：

```text
wait()
pipe
signal
semaphore
mutex
```

不能靠“感觉上应该谁先执行”。

# 练习 5：用 pipe 解决父子进程执行顺序问题

## 目标

理解：

```text
如果父进程必须等子进程完成某件事，不能靠 sleep 猜。
应该使用同步机制。
```

这里用管道 pipe 做同步。

------

## 示例代码：`fork_sync_pipe.c`

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

int main(void) {
    int pipefd[2];

    if (pipe(pipefd) == -1) {
        perror("pipe");
        return 1;
    }

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        close(pipefd[0]);

        printf("Child: doing some important work...\n");
        sleep(2);
        printf("Child: work finished, notifying parent.\n");

        char signal_byte = 'X';
        write(pipefd[1], &signal_byte, 1);

        close(pipefd[1]);
        _exit(0);
    } else {
        close(pipefd[1]);

        printf("Parent: waiting for child notification...\n");

        char buffer;
        read(pipefd[0], &buffer, 1);

        printf("Parent: received notification. Now parent continues.\n");

        close(pipefd[0]);
        waitpid(pid, NULL, 0);
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_sync_pipe.c -o fork_sync_pipe
./fork_sync_pipe
```

------

## 你应该观察什么？

输出顺序一定是：

```text
Parent: waiting for child notification...
Child: doing some important work...
Child: work finished, notifying parent.
Parent: received notification. Now parent continues.
```

------

## 通俗解释

管道可以理解成父子进程之间的一根小水管。

```text
父进程 read() 等待。
子进程 write() 发送一个字节。
父进程读到字节后继续执行。
```

重点不是传递了什么数据。

重点是：

```text
read() 在没有数据时会阻塞。
write() 写入数据后，read() 才返回。
```

这就实现了同步。

# 练习 6：用信号同步，避免 fork() 后的竞争条件

## 目标

对应第 24.5 节。

理解：

```text
信号也可以用来做父子进程同步。
但要先屏蔮信号，再等待信号，避免信号提前到达导致丢失。
```

------

## 示例代码：`fork_sync_signal.c`

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <signal.h>
#include <sys/wait.h>

static volatile sig_atomic_t got_signal = 0;

static void handler(int sig) {
    (void)sig;
    got_signal = 1;
}

int main(void) {
    sigset_t block_set;
    sigset_t old_set;

    sigemptyset(&block_set);
    sigaddset(&block_set, SIGUSR1);

    if (sigprocmask(SIG_BLOCK, &block_set, &old_set) == -1) {
        perror("sigprocmask");
        return 1;
    }

    struct sigaction sa;
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    if (sigaction(SIGUSR1, &sa, NULL) == -1) {
        perror("sigaction");
        return 1;
    }

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("Child: doing work...\n");
        sleep(2);
        printf("Child: sending SIGUSR1 to parent.\n");

        kill(getppid(), SIGUSR1);

        _exit(0);
    } else {
        printf("Parent: waiting for SIGUSR1...\n");

        while (!got_signal) {
            sigsuspend(&old_set);
        }

        printf("Parent: got SIGUSR1, now continue.\n");

        sigprocmask(SIG_SETMASK, &old_set, NULL);
        waitpid(pid, NULL, 0);
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_sync_signal.c -o fork_sync_signal
./fork_sync_signal
```

------

## 你应该观察什么？

父进程会等到子进程发出 `SIGUSR1` 后才继续。

------

## 通俗解释

这里的关键点是：

```c
sigprocmask(SIG_BLOCK, &block_set, &old_set);
```

父进程先把 `SIGUSR1` 屏蔽住。

为什么？

因为如果子进程很快发信号，而父进程还没准备好等待，就可能出现：

```text
信号已经来了，
父进程后面才开始等，
结果父进程永远等不到。
```

这就是信号同步中的经典竞争条件。

正确做法是：

```text
先屏蔮信号
安装信号处理器
fork 子进程
父进程用 sigsuspend() 原子地解除屏蔽并等待信号
```

这比单纯 `pause()` 更可靠。

# 练习 7：理解 exit() 和 _exit() 的区别

## 目标

理解：

```text
exit() 会刷新 stdio 缓冲区。
_exit() 不刷新 stdio 缓冲区。
```

------

## 示例代码：`exit_vs__exit.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

int main(int argc, char *argv[]) {
    printf("This message has no newline...");

    if (argc >= 2 && strcmp(argv[1], "_exit") == 0) {
        _exit(0);
    } else {
        exit(0);
    }
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 exit_vs__exit.c -o exit_vs__exit

./exit_vs__exit
echo

./exit_vs__exit _exit
echo
```

------

## 你应该观察什么？

运行：

```bash
./exit_vs__exit
```

大概率能看到输出：

```text
This message has no newline...
```

运行：

```bash
./exit_vs__exit _exit
```

可能看不到输出。

------

## 通俗解释

`printf()` 不是每次都马上写到屏幕。

它通常先写到用户态缓冲区。

```text
printf() → stdio 缓冲区 → 真正的文件描述符 → 终端
```

`exit()` 会帮你把缓冲区刷新出去。

`_exit()` 不管这些，直接让进程退出。

所以：

```text
exit() 是“收拾好再走”。
_exit() 是“立刻离开”。
```

# 练习 8：观察 fork() 和 stdio 缓冲区的交互

## 目标

理解第 25.4 节：

```text
fork() 会复制用户态 stdio 缓冲区。
如果 fork 前缓冲区里有内容，父子进程 exit() 时可能各刷新一次。
```

------

## 示例代码：`fork_stdio_buffer.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

int main(int argc, char *argv[]) {
    printf("HELLO");

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (argc >= 2 && strcmp(argv[1], "_exit") == 0) {
        _exit(0);
    } else {
        exit(0);
    }
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fork_stdio_buffer.c -o fork_stdio_buffer

./fork_stdio_buffer
echo

./fork_stdio_buffer _exit
echo
```

------

## 你应该观察什么？

运行：

```bash
./fork_stdio_buffer
```

你可能看到：

```text
HELLOHELLO
```

运行：

```bash
./fork_stdio_buffer _exit
```

你可能看不到输出。

------

## 通俗解释

这行代码没有换行：

```c
printf("HELLO");
```

所以 `"HELLO"` 可能还在 stdio 缓冲区里。

然后执行：

```c
fork();
```

缓冲区也被复制了一份。

于是：

```text
父进程缓冲区里有 HELLO
子进程缓冲区里也有 HELLO
```

如果父子都调用 `exit()`，它们都会刷新缓冲区。

所以可能输出两次。

这就是为什么在经典写法里：

```c
if (pid == 0) {
    exec(...);
    _exit(127);
}
```

子进程 exec 失败后通常用 `_exit()`，避免重复刷新父进程继承来的缓冲区。

# 练习 9：使用 atexit() 注册退出处理程序

## 目标

理解：

```text
exit() 会执行 atexit() 注册的退出处理程序。
_exit() 不会执行这些处理程序。
```

------

## 示例代码：`atexit_demo.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

static void cleanup_one(void) {
    printf("cleanup_one called\n");
}

static void cleanup_two(void) {
    printf("cleanup_two called\n");
}

int main(int argc, char *argv[]) {
    if (atexit(cleanup_one) != 0) {
        perror("atexit cleanup_one");
        return 1;
    }

    if (atexit(cleanup_two) != 0) {
        perror("atexit cleanup_two");
        return 1;
    }

    printf("Main function is about to exit.\n");

    if (argc >= 2 && strcmp(argv[1], "_exit") == 0) {
        _exit(0);
    } else {
        exit(0);
    }
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 atexit_demo.c -o atexit_demo

./atexit_demo

./atexit_demo _exit
```

------

## 你应该观察什么？

普通 `exit()`：

```text
Main function is about to exit.
cleanup_two called
cleanup_one called
```

注意顺序是后注册的先执行。

使用 `_exit()`：

```text
Main function is about to exit.
```

甚至在某些情况下，如果缓冲没有刷新，输出也可能缺失。

------

## 通俗解释

`atexit()` 就像登记临终遗言：

```text
进程正常 exit() 时，系统会帮你一个个调用。
```

但 `_exit()` 太直接了：

```text
不执行退出处理程序，不刷新 stdio，直接退出。
```

# 练习 10：用 waitpid() 获取子进程退出状态

## 目标

理解：

```text
子进程退出后，父进程可以通过 waitpid() 获取它的结束原因。
status 不能直接当退出码，要用宏解析。
```

------

## 示例代码：`wait_status.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

int main(int argc, char *argv[]) {
    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        if (argc >= 2 && argv[1][0] == 's') {
            printf("Child: I will terminate myself with SIGTERM.\n");
            raise(SIGTERM);
        } else {
            printf("Child: I will exit normally with status 42.\n");
            _exit(42);
        }
    } else {
        int status;

        if (waitpid(pid, &status, 0) == -1) {
            perror("waitpid");
            return 1;
        }

        if (WIFEXITED(status)) {
            printf("Parent: child exited normally.\n");
            printf("Parent: exit status = %d\n", WEXITSTATUS(status));
        } else if (WIFSIGNALED(status)) {
            printf("Parent: child was killed by signal.\n");
            printf("Parent: signal number = %d\n", WTERMSIG(status));
        } else {
            printf("Parent: child ended in another way.\n");
        }
    }

    return 0;
}
```

```bash

```

## 你应该观察什么？

正常退出：

```text

Parent: exit status = 42
```

被信号终止：

```text

```

## 通俗解释

`waitpid()` 拿到的 `status` 是一个编码后的状态值，不只是退出码。

所以不能这样直接用：

```c

```

要用这些宏：

```c

WEXITSTATUS(status)
WIFSIGNALED(status)
WTERMSIG(status)
```

可以理解成：

```text
status 是一个包裹。
你需要用专门的工具拆开它。
```

# 练习 11：用 WNOHANG 实现非阻塞等待

## 目标

理解：

```text
waitpid(pid, &status, WNOHANG) 不会阻塞。
如果子进程还没结束，它返回 0。
```

------

## 示例代码：`wait_nohang.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("Child: sleeping for 5 seconds...\n");
        sleep(5);
        printf("Child: exiting now.\n");
        _exit(77);
    } else {
        int status;

        while (1) {
            pid_t result = waitpid(pid, &status, WNOHANG);

            if (result == -1) {
                perror("waitpid");
                return 1;
            }

            if (result == 0) {
                printf("Parent: child has not exited yet. I can do other work.\n");
                sleep(1);
            } else {
                printf("Parent: child exited.\n");

                if (WIFEXITED(status)) {
                    printf("Parent: child exit status = %d\n",
                           WEXITSTATUS(status));
                }

                break;
            }
        }
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 wait_nohang.c -o wait_nohang
./wait_nohang
```

------

## 你应该观察什么？

父进程不会卡死在 `waitpid()` 上。

它会每秒输出：

```text
Parent: child has not exited yet. I can do other work.
```

等子进程退出后，再回收它。

------

## 通俗解释

普通 `waitpid()` 像是在门口一直等孩子回来：

```text
孩子不回来，父亲一直站着不动。
```

`WNOHANG` 像是父亲看一眼：

```text
孩子回来了吗？
没回来？那我先去干别的，一会儿再看。
```

这在服务器程序里很常用，因为服务器不能为了等一个子进程就停止处理其他事情。

# 练习 14：使用 SIGCHLD 自动回收多个子进程

## 目标

理解：

```text
子进程结束时，父进程会收到 SIGCHLD。
父进程可以在 SIGCHLD 处理程序里调用 waitpid() 回收子进程。
```

重点：

```text
处理 SIGCHLD 时通常要 while 循环 waitpid(-1, ..., WNOHANG)。
因为多个子进程可能同时结束，但 SIGCHLD 不一定一一排队。
```

------

## 示例代码：`sigchld_reap.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
#include <errno.h>

static volatile sig_atomic_t live_children = 0;

static void sigchld_handler(int sig) {
    (void)sig;

    int saved_errno = errno;

    while (1) {
        pid_t pid = waitpid(-1, NULL, WNOHANG);

        if (pid > 0) {
            live_children--;
        } else {
            break;
        }
    }

    errno = saved_errno;
}

int main(void) {
    struct sigaction sa;
    sigset_t block_set;
    sigset_t old_set;

    sigemptyset(&block_set);
    sigaddset(&block_set, SIGCHLD);

    if (sigprocmask(SIG_BLOCK, &block_set, &old_set) == -1) {
        perror("sigprocmask");
        return 1;
    }

    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;

    if (sigaction(SIGCHLD, &sa, NULL) == -1) {
        perror("sigaction");
        return 1;
    }

    for (int i = 0; i < 5; i++) {
        live_children++;

        pid_t pid = fork();

        if (pid == -1) {
            perror("fork");
            live_children--;
            continue;
        }

        if (pid == 0) {
            printf("Child %d: PID = %ld, sleeping %d seconds\n",
                   i, (long)getpid(), i + 1);
            sleep(i + 1);
            _exit(100 + i);
        }
    }

    if (sigprocmask(SIG_SETMASK, &old_set, NULL) == -1) {
        perror("sigprocmask restore");
        return 1;
    }

    while (live_children > 0) {
        printf("Parent: live children = %d\n", live_children);
        sleep(1);
    }

    printf("Parent: all children reaped.\n");

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 sigchld_reap.c -o sigchld_reap
./sigchld_reap
```

------

## 你应该观察什么？

父进程没有显式在主流程里一个个 `wait()`。

但子进程结束后，`SIGCHLD` 处理程序会自动回收它们。

------

## 通俗解释

子进程退出时，内核会通知父进程：

```text
你的孩子状态变化了。
```

这个通知就是 `SIGCHLD`。

但是注意：

```text
死了 5 个子进程，不一定收到 5 次 SIGCHLD。
```

所以处理程序里要写：

```c
while (waitpid(-1, NULL, WNOHANG) > 0) {
    ...
}
```

意思是：

```text
既然来了一个 SIGCHLD，我就把所有已经死掉的孩子都回收掉。
```

# 练习 15：使用 exec 执行新程序

## 目标

理解：

```text
exec() 不创建新进程。
exec() 用新程序替换当前进程的程序映像。
exec() 成功后不会返回。
```

------

## 示例代码：`fork_exec_ls.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("Child: before exec, PID = %ld\n", (long)getpid());

        execlp("ls", "ls", "-l", "/tmp", NULL);

        perror("execlp failed");
        _exit(127);
    } else {
        int status;

        printf("Parent: child PID = %ld\n", (long)pid);

        waitpid(pid, &status, 0);

        if (WIFEXITED(status)) {
            printf("Parent: child exit status = %d\n",
                   WEXITSTATUS(status));
        }
    }

    return 0;
}
```

```bash
./fork_exec_ls
```

## 你应该观察什么？

你会看到子进程执行了：

```bash

```

但这句：

```c

```

正常情况下不会执行。

------

## 通俗解释

`execlp()` 成功后，子进程不再运行你写的这个 C 程序。

它变成了 `ls` 程序。

所以：

```text
fork() 负责创建子进程。
exec() 负责让子进程变成另一个程序。
waitpid() 负责父进程等待子进程结束。
```

这就是 shell 执行外部命令的核心流程。

# 练习 17：观察 exec 后文件描述符是否会被继承

## 目标

理解第 27.4 节：

```text
exec() 默认不会关闭已打开的文件描述符。
除非设置了 FD_CLOEXEC。
```

------

## 示例代码：`fd_cloexec_demo.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>
#include <sys/wait.h>

int main(int argc, char *argv[]) {
    int fd = open("secret_file.txt", O_CREAT | O_RDWR | O_TRUNC, 0644);

    if (fd == -1) {
        perror("open");
        return 1;
    }

    write(fd, "This is a secret file.\n", 23);

    printf("Parent: opened secret_file.txt as fd %d\n", fd);

    if (argc >= 2 && strcmp(argv[1], "cloexec") == 0) {
        int flags = fcntl(fd, F_GETFD);

        if (flags == -1) {
            perror("fcntl F_GETFD");
            close(fd);
            return 1;
        }

        flags |= FD_CLOEXEC;

        if (fcntl(fd, F_SETFD, flags) == -1) {
            perror("fcntl F_SETFD");
            close(fd);
            return 1;
        }

        printf("Parent: FD_CLOEXEC has been set on fd %d\n", fd);
    }

    pid_t pid = fork();

    if (pid == -1) {
        perror("fork");
        close(fd);
        return 1;
    }

    if (pid == 0) {
        printf("Child: executing ls -l /proc/self/fd\n");

        execlp("ls", "ls", "-l", "/proc/self/fd", NULL);

        perror("execlp");
        _exit(127);
    } else {
        waitpid(pid, NULL, 0);
        close(fd);
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 fd_cloexec_demo.c -o fd_cloexec_demo

./fd_cloexec_demo

./fd_cloexec_demo cloexec
```

------

## 你应该观察什么？

第一次运行时，你可能在 `/proc/self/fd` 里看到某个 fd 指向：

```text
secret_file.txt
```

第二次运行设置了 `FD_CLOEXEC`，执行 `exec` 后，这个 fd 应该不会再被新程序继承。

------

## 通俗解释

默认情况下：

```text
fork() 会继承文件描述符。
exec() 也不会主动关闭文件描述符。
```

所以新程序可能会拿到旧程序打开的文件。

这有时候是好事。

比如 shell 重定向：

```bash
ls > out.txt
```

shell 会先在子进程里把标准输出重定向到 `out.txt`，然后 exec `ls`。

因为 exec 不关闭 stdout，所以 `ls` 的输出就进了文件。

但有时候这是坏事。

比如：

```text
父进程打开了敏感文件。
子进程 exec 了一个不可信程序。
不可信程序继承了这个文件描述符。
```

这就有泄露风险。

所以可以设置：

```c
FD_CLOEXEC
```

意思是：

```text
一旦 exec，就自动关闭这个 fd。
```

# 练习 18：自己实现一个简化版 system()

## 目标

理解：

```text
system("命令") 本质上是：
fork()
子进程 exec /bin/sh -c 命令
父进程 waitpid()
```

------

## 示例代码：`my_system.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>
#include <errno.h>

int my_system(const char *command) {
    if (command == NULL) {
        return 1;
    }

    pid_t pid = fork();

    if (pid == -1) {
        return -1;
    }

    if (pid == 0) {
        execl("/bin/sh", "sh", "-c", command, NULL);
        _exit(127);
    }

    int status;

    while (waitpid(pid, &status, 0) == -1) {
        if (errno == EINTR) {
            continue;
        }

        return -1;
    }

    return status;
}

int main(void) {
    int status = my_system("echo Hello from my_system; ls -l /tmp | head");

    if (status == -1) {
        perror("my_system");
        return 1;
    }

    if (WIFEXITED(status)) {
        printf("Command exited with status %d\n", WEXITSTATUS(status));
    } else if (WIFSIGNALED(status)) {
        printf("Command killed by signal %d\n", WTERMSIG(status));
    }

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 my_system.c -o my_system
./my_system
```

------

## 你应该观察什么？

它会执行 shell 命令：

```bash
echo Hello from my_system; ls -l /tmp | head
```

------

## 通俗解释

`system()` 的方便之处是：

```text
你可以直接写 shell 命令。
```

比如：

```c
system("ls -l | grep txt");
```

但它的代价是：

```text
要启动 shell。
有安全风险。
效率比直接 exec 慢。
```

尤其不能随便拼接用户输入：

```c
sprintf(cmd, "cat %s", user_input);
system(cmd);
```

如果用户输入：

```bash
abc; rm important_file
```

那 shell 会把它当成两条命令。

所以实际开发中，如果参数来自用户，尽量用 `fork() + exec()`，不要拼接字符串交给 `system()`。

# 练习 19：安全使用 vfork() 后立刻 exec()

## 目标

理解：

```text
vfork() 和 fork() 不同。
vfork() 后，子进程在 exec() 或 _exit() 前，父进程会被阻塞。
子进程不应该修改父进程内存，不应该 return。
```

------

## 示例代码：`vfork_exec.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    printf("Parent: before vfork, PID = %ld\n", (long)getpid());

    pid_t pid = vfork();

    if (pid == -1) {
        perror("vfork");
        return 1;
    }

    if (pid == 0) {
        execlp("echo", "echo", "Hello from child after vfork + exec", NULL);

        perror("execlp");
        _exit(127);
    }

    int status;
    waitpid(pid, &status, 0);

    printf("Parent: child finished.\n");

    return 0;
}
```

------

## 编译运行

```bash
gcc -Wall -Wextra -O2 vfork_exec.c -o vfork_exec
./vfork_exec
```

------

## 你应该观察什么？

子进程会执行 `echo`。

父进程等子进程 exec/退出后继续。

------

## 通俗解释

`vfork()` 的存在主要是历史原因和性能优化。

它适合这种情况：

```text
创建子进程后，子进程马上 exec 新程序。
```

但你要记住：

```text
vfork() 子进程不要修改变量。
不要调用复杂函数。
不要从当前函数 return。
要么 exec()，要么 _exit()。
```

普通学习和普通开发里，优先用：

```c
fork()
```

不要随便用 `vfork()`。

# 练习 20：使用 clone() 观察共享内存空间的效果

## 目标

理解第 28.2 节：

```c
    printf("Child: initial shared_value = %d\n", shared_value);
    shared_value = 99;
    printf("Child: changed shared_value to %d\n", shared_value);

    return 0;
}

int main(int argc, char *argv[]) {
    char *stack = malloc(STACK_SIZE);

    if (stack == NULL) {
        perror("malloc");
        return 1;
    }

    char *stack_top = stack + STACK_SIZE;

    int flags = SIGCHLD;

    if (argc >= 2 && strcmp(argv[1], "vm") == 0) {
        flags |= CLONE_VM;
        printf("Using clone() with CLONE_VM.\n");
    } else {
        printf("Using clone() without CLONE_VM.\n");
    }

    printf("Parent: before clone, shared_value = %d\n", shared_value);

    pid_t pid = clone(child_func, stack_top, flags, NULL);

    if (pid == -1) {
        perror("clone");
        free(stack);
        return 1;
    }

    waitpid(pid, NULL, 0);

    printf("Parent: after child exits, shared_value = %d\n", shared_value);

    free(stack);

    return 0;
}
```

## 通俗解释

普通 `fork()` 后：

```text
父子进程内存独立。
```

而 `clone()` 可以选择是否共享内存。

如果加上：

```c
CLONE_VM
```

父子任务共享地址空间。

所以子进程修改：

```c
shared_value = 99;
```

父进程也能看到变化。

这就是线程实现的基础思想之一：

```text
线程之间共享同一个进程地址空间。
```

不过真实线程还会共享更多东西，例如文件描述符、信号处理方式、线程组等。

# 练习 21：综合项目，写一个迷你 shell

## 目标

```text

```

这个练习非常重要，因为 shell 正是理解这些章节的最佳例子。

------

## 功能

这个迷你 shell 支持：

```bash

exit
```

不支持复杂功能：

```text
不支持管道 |
不支持引号
不支持后台运行 &
不支持复杂变量展开
```

------

## 示例代码：`mini_shell.c`

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <fcntl.h>
#include <sys/wait.h>

#define MAX_LINE 1024
#define MAX_ARGS 64

static void parse_line(char *line, char *args[]) {
    int i = 0;

    char *token = strtok(line, " \t\n");

    while (token != NULL && i < MAX_ARGS - 1) {
        args[i++] = token;
        token = strtok(NULL, " \t\n");
    }

    args[i] = NULL;
}

static int handle_redirection(char *args[]) {
    for (int i = 0; args[i] != NULL; i++) {
        if (strcmp(args[i], ">") == 0) {
            if (args[i + 1] == NULL) {
                fprintf(stderr, "mini-shell: missing filename after >\n");
                return -1;
            }

            int fd = open(args[i + 1],
                          O_CREAT | O_WRONLY | O_TRUNC,
                          0644);

            if (fd == -1) {
                perror("open");
                return -1;
            }

            if (dup2(fd, STDOUT_FILENO) == -1) {
                perror("dup2");
                close(fd);
                return -1;
            }

            close(fd);

            args[i] = NULL;
            return 0;
        }
    }

    return 0;
}

int main(void) {
    char line[MAX_LINE];
    char *args[MAX_ARGS];

    while (1) {
        printf("mini-shell> ");
        fflush(stdout);

        if (fgets(line, sizeof(line), stdin) == NULL) {
            printf("\n");
            break;
        }

        parse_line(line, args);

        if (args[0] == NULL) {
            continue;
        }

        if (strcmp(args[0], "exit") == 0) {
            break;
        }

        if (strcmp(args[0], "cd") == 0) {
            const char *target = args[1];

            if (target == NULL) {
                target = getenv("HOME");
            }

            if (target == NULL) {
                fprintf(stderr, "mini-shell: HOME not set\n");
                continue;
            }

            if (chdir(target) == -1) {
                perror("cd");
            }

            continue;
        }

        pid_t pid = fork();

        if (pid == -1) {
            perror("fork");
            continue;
        }

        if (pid == 0) {
            if (handle_redirection(args) == -1) {
                _exit(1);
            }

            execvp(args[0], args);

            perror("execvp");
            _exit(127);
        } else {
            int status;

            if (waitpid(pid, &status, 0) == -1) {
                perror("waitpid");
                continue;
            }

            if (WIFEXITED(status)) {
                int code = WEXITSTATUS(status);

                if (code != 0) {
                    printf("mini-shell: command exited with status %d\n", code);
                }
            } else if (WIFSIGNALED(status)) {
                printf("mini-shell: command killed by signal %d\n",
                       WTERMSIG(status));
            }
        }
    }

    return 0;
}
```

## 通俗解释

你输入：

```bash
ls -l > out.txt
```

这个迷你 shell 做了这些事：

```text
1. 解析命令，得到 args = {"ls", "-l", ">", "out.txt", NULL}
2. fork() 创建子进程
3. 子进程发现有 >
4. 子进程 open("out.txt")
5. 子进程 dup2(fd, STDOUT_FILENO)
6. 子进程 execvp("ls", args)
7. ls 程序开始运行
8. ls 的 stdout 已经被改成 out.txt
9. 父进程 waitpid() 等待 ls 结束
```

这里最重要的地方是：

```text
重定向必须在子进程里做。
```

为什么？

如果父进程自己把 stdout 改成文件，那么 shell 自己后面的提示符也会写进文件。

所以正确做法是：

```text
父进程保持原样。
子进程修改文件描述符。
子进程 exec 新程序。
```

这正是 Linux shell 的核心思想。

# 你做练习时要特别注意的几个点

## 1. 不要假设父进程一定先运行

这种代码是不可靠的：

```c
pid_t pid = fork();

if (pid == 0) {
    // 假设子进程先运行
} else {
    // 假设父进程后运行
}
```

正确做法是用同步：

```text
wait()
pipe
signal
semaphore
```

------

## 2. 子进程 exec 失败后优先用 _exit()

经典写法：

```c
if (pid == 0) {
    execlp("ls", "ls", NULL);
    perror("execlp");
    _exit(127);
}
```

因为子进程是 fork 出来的，可能继承了父进程的 stdio 缓冲区。

用 `exit()` 可能导致重复刷新。

------

## 3. waitpid() 的 status 必须用宏解析

不要直接把 `status` 当退出码。

正确方式：

```c
if (WIFEXITED(status)) {
    printf("%d\n", WEXITSTATUS(status));
}
```

------

## 4. SIGCHLD 处理程序中不要做复杂事情

不要在信号处理程序中随便写：

```c
printf()
malloc()
free()
```

更安全的做法：

```text
只调用 waitpid()
只修改 sig_atomic_t 类型变量
必要时用 write()
```

------

## 5. exec 成功后不会返回

所以这类代码：

```c
execvp(args[0], args);
printf("after exec\n");
```

如果 exec 成功，`printf` 不会执行。

如果执行了，说明 exec 失败了。

# 最后给你一个核心记忆公式

这五章最重要的代码模式就是：

```c
pid_t pid = fork();

if (pid == 0) {
    execvp(program, args);
    _exit(127);
} else {
    waitpid(pid, &status, 0);
}
```

这段模式背后对应的是：

```text
fork()：创建子进程
execvp()：子进程执行新程序
_exit()：exec 失败时直接退出
waitpid()：父进程回收子进程
status：父进程判断子进程怎么结束
```

只要你把这套模式真正写熟，第 24–28 章的大部分重点就已经掌握了。
