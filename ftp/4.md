这是 FTP 最容易让人困惑的一部分，因为前面三版都只有一个 socket：

```text
客户端
   │
   ▼
控制连接(2100)

   ▼
```

但是 FTP 真正工作时是：

```text
                控制连接
客户端  <---------------------->  2100

                数据连接
客户端  <---------------------->  50001
```

也就是说：

```text
命令走控制连接
数据走数据连接
```

例如：

```text
LIST
RETR
STOR
```

都必须额外建立一个数据连接。

------

-   **被动模式**：客户端发送 `PASV` 命令，服务器开启一个临时 TCP 端口（通常是一个随机的高位端口），并将 IP 和端口号告诉客户端。客户端主动连接到这个端口，服务器通过这个连接进行数据传输。
-   **数据连接**：每次 `LIST`、`RETR`、`STOR` 等需要传输数据的命令，都会使用通过 `PASV` 建立的监听 socket 来 **accept** 一个实际的数据 socket。



# 新增会话状态

在 FtpSession 增加：

`pasvListenFd` 和 `pasvPort` 是 **FTP 被动模式（PASV）** 实现中的核心状态变量。它们用于在服务器与客户端之间建立**数据连接**（用于传输文件或目录列表）。

```cpp
int pasvListenFd = -1;

int pasvPort = 0;
```

# 新增关闭函数

```cpp
void closePassive()
{//关闭被动模式的监听 socket（如果当前存在）。
    if (pasvListenFd >= 0)
    {//将成员变量重置为“无被动监听”状态
        close(pasvListenFd);

        pasvListenFd = -1;

        pasvPort = 0;
    }
}
```

| 场景                                          | 说明                                                         |
| :-------------------------------------------- | :----------------------------------------------------------- |
| **1. 收到新的 `PASV` 命令**                   | 客户端可能连续发送两次 `PASV`，此时应关闭旧的监听 socket，然后创建新的。 |
| **2. 数据命令（`LIST`/`RETR`/`STOR`）执行前** | 在这些命令中，会调用 `acceptDataConnection`，其中会先 `closePassive()`？不一定。标准流程是：`PASV` 创建监听 → 数据命令 `accept` 获得数据 socket → 然后应立即关闭监听 socket（单次使用）。`closePassive` 正好做这件事。 |
| **3. 数据连接超时**                           | 如果客户端长时间不连接，`acceptDataConnection` 中的 `select` 超时后，应调用 `closePassive()` 清理监听 socket，并回复错误。 |
| **4. 会话结束（`run()` 退出）**               | 客户端断开连接时，应调用 `closePassive()` 确保没有遗留的监听 socket。 |
| **5. 异常处理**                               | 当 `accept` 失败或数据传输异常时，应清理被动监听资源。       |

# 新增创建监听Socket

```cpp
int createListenSocket(int port)
{
    int fd =
        socket(
            AF_INET,
            SOCK_STREAM,
            0);

    if (fd < 0)
    {
        return -1;
    }

    int opt = 1;

    setsockopt(
        fd,
        SOL_SOCKET,
        SO_REUSEADDR,
        &opt,
        sizeof(opt));

    sockaddr_in addr {};

    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr =
        htonl(INADDR_ANY);

    addr.sin_port =
        htons(port);

    if (bind(
            fd,
            reinterpret_cast<sockaddr*>(&addr),
            sizeof(addr)) < 0)
    {
        close(fd);
        return -1;
    }

    if (listen(fd, 1) < 0)
    {
        close(fd);
        return -1;
    }

    return fd;
}
```

# handlePASV()

这是本阶段核心。

```cpp
void handlePASV()
{//有限登陆PASV
    if (!loggedIn)
    {
        sendReply(
            530,
            "Please login");
        return;
    }

    //如果之前已经有一个被动监听 socket（例如客户端连续发送两次 PASV），先关闭旧监听，释放资源，重置 pasvListenFd 和 pasvPort。
    closePassive();

    //--------------------------------------------------
    // 为简单起见固定50000端口
    // Stage7再改随机端口
    //--------------------------------------------------
// 创建监听 socket（目前固定端口）
    pasvPort = 50000;

    //createListenSocket 是一个辅助函数，负责创建 socket、绑定、监听，并返回 fd（若失败返回 -1）。
    pasvListenFd =
        createListenSocket(
            pasvPort);

    if (pasvListenFd < 0)
    {
        sendReply(
            425,
            "Cannot open passive connection");

        return;
    }

    //--------------------------------------------------
    // FTP格式:
    //
    // 127,0,0,1,195,80
    //
    // 195*256+80=50000
    //--------------------------------------------------
//FTP 被动模式响应格式：227 Entering Passive Mode (h1,h2,h3,h4,p1,p2)
    sendReply(
        227,
        "Entering Passive Mode "
        "(127,0,0,1,195,80)");
}
```

# acceptDataConnection()

-   **接受客户端的数据连接**：在 `PASV` 之后，客户端会根据 `227` 响应中的 IP 和端口主动连接服务器。服务器调用 `accept` 接收这个连接，得到一个新的 socket（`dataFd`），用于后续实际的数据传输。
-   **清理被动监听资源**：调用 `closePassive()` 关闭监听 socket，重置相关状态。
-   **返回数据 socket 描述符**：供上层函数（如 `handleLIST`、`handleRETR`）使用，传输完成后上层再关闭 `dataFd`。

```cpp
int acceptDataConnection()
{//如果当前会话没有处于被动监听状态（即未调用 PASV 或监听已被关闭），则直接返回 -1，调用方应处理错误（例如回复 425）。
    if (pasvListenFd < 0)
    {
        return -1;
    }
//准备accept  addr 将存储客户端的地址信息（可用于日志记录或安全检查）。

//len 必须初始化为 sizeof(addr)。
    
    sockaddr_in addr {};

    socklen_t len =
        sizeof(addr);
// 打印等待日志（调试用）
    std::cout
        << "[PASV] waiting data connection...\n";
// 调用 accept（阻塞）：
    //因为 pasvListenFd 是监听 socket，accept 会阻塞直到客户端连接过来。阻塞的风险：如果客户端永远不连接，这个线程会卡住。后续改进应添加超时机制（如 select 或 poll）。
    //成功时返回一个新的 socket 描述符（dataFd），专门用于这次数据传输。
    int dataFd =
        accept(
            pasvListenFd,
            reinterpret_cast<sockaddr*>(
                &addr),
            &len);
//立即关闭监听 socket，被动模式的监听 socket 设计为单次使用：一旦 accept 成功（或失败），就立即关闭监听 socket，重置 pasvListenFd 和 pasvPort。
    closePassive();

    if (dataFd >= 0)
    {
        std::cout
            << "[PASV] data connected\n";
    }
//返回数据 socket
    return dataFd;
}
```

# handleTESTDATA()

-   **测试数据连接**：模拟一个数据传输任务，向客户端发送一段固定的文本（`"Hello From Data Connection\r\n"`），然后关闭连接。
-   **验证完整的数据连接流程**：包括登录检查、回复 `150`、建立数据连接（通过 `acceptDataConnection`）、发送数据、回复 `226`。
-   **辅助开发调试**：在不实现完整 `LIST`/`RETR` 命令的情况下，快速验证被动模式的核心机制。

```cpp
void handleTESTDATA()
{
    if (!loggedIn)
    {
        sendReply(
            530,
            "Please login");
        return;
    }

    //150 表示“文件状态正确，即将打开数据连接”。客户端收到后会准备接收数据。
    sendReply(
        150,
        "Opening data connection");

    //建立数据连接，接受与客户端的连接
    int dataFd =
        acceptDataConnection();

    if (dataFd < 0)
    {
        sendReply(
            425,
            "Data connection failed");

        return;
    }

    //通过数据连接发送测试数据
    const char* msg =
        "Hello From Data Connection\r\n";

    send(
        dataFd,
        msg,
        strlen(msg),
        0);

    //数据发送完毕，关闭数据 socket，释放资源。
    close(dataFd);

    //226 表示数据传输成功完成。客户端收到后知道传输结束。
    sendReply(
        226,
        "Transfer complete");
}
```
