## 第 1 周｜10/14--10/20：Go 语言、TCP 和测试底座

## 3. 技术"掌握到什么程度"验收表

### Go：必须掌握

- **语法/工程**：能独立建 module、拆 package、设计 interface、处理 error、写 table-driven tests；不要求背所有标准库 API。
    
- **并发**：会写 goroutine、channel、Mutex、WaitGroup、context；解释竞态、死锁、泄漏；`go test -race` 检查通过。
    
- **网络**：能写 TCP Client/Server、长度帧、读写超时、异常断线处理；理解 TCP 是字节流而非消息流。
    
- **调试**：会看日志、stack trace、测试失败、race 输出；能够独立定位并修复至少 3 个真实 Bug。
    
- **面试**：理解 slice、map、interface、GMP、GC、内存逃逸的基本原理；不强求背 runtime 源码。
    

### RPC：必须交付

- **MVP 硬性**：两个服务可被远程调用；并发请求 ID 正确匹配；超时清理；断线唤醒；畸形输入不会 panic；自动化测试可重复运行。
    
- **增强优先**：静态服务发现 + 轮询负载均衡 + 业务 Demo；优先于复杂熔断、注册中心、Raft。
    
- **性能**：有可复现 Benchmark，记录环境、并发、payload、QPS、延迟、错误率；不承诺固定 QPS。
    
- **文档**：架构图、API 示例、运行/测试/压测命令、技术取舍、局限、已知问题。
    
- **讲解**：能回答"为什么有 pending map、为什么同连接写要同步、超时与服务端取消区别、重试幂等性、连接断开如何清理"。
    

### MySQL / Redis：普通后端必备，不是数据库内核

- MySQL：自己建表、写 CRUD、参数化查询；能解释 B+Tree、联合索引最左前缀、事务 ACID、隔离级别、常见慢查询定位。
    
- Redis：会使用基础数据类型和 TTL；能解释缓存穿透、击穿、雪崩；业务 Demo 不强制接入 Redis，避免无意义堆栈。
    
- 不需要研究存储引擎源码或复杂分布式数据库。
    

### 6.5840：明确边界

- MapReduce：能解释 Coordinator/Worker、任务分配、失败重试、文件输出；尽量通过课程测试。
    
- Raft：能画 Follower/Candidate/Leader 状态机，解释 term、投票、心跳、选举超时；尽量完成选举测试。
    
- 日志复制/持久化/快照/KV/Sharding：**非 12/15 硬指标**；时间不够先停。
    
- 实验必须遵守课程学术诚信规则，不复制公开答案。
    

### 开源 / OSPP：真实贡献标准

- 能 clone、构建、跑测试；读懂一个局部模块的调用链。
    
- 提供复现步骤、预期/实际结果；修改代码同时补测试；遵守贡献规范并响应 Review。
    
- **最低可控成果**：一份质量较高的问题分析或一个已提交的实质性 PR；**争取**合入，不能保证。
    
- OSPP 需要核实当期项目开放状态、申请资格、名额和导师安排；不要假定"全年开放=任意项目可随时参加"。
